# Privacy Counsel — Персональные данные (Vector Legal)

Адаптация [claude-for-legal/privacy-legal](https://github.com/anthropics/claude-for-legal)
(Anthropic, Apache-2.0) под российское право (152-ФЗ «О персональных данных»)
и Hermes Agent.

## Что это

In-house приватность по 152-ФЗ: поручения на обработку разбираются против
**playbook оператора** (не «рыночного стандарта»), запросы субъектов
обрабатываются по процедуре с 30-дневным сроком и журналом, новые обработки
проходят триаж (нужна ли оценка вреда по ст. 18.1, уведомление РКН,
особые режимы биометрии/трансгранички), политика сверяется с практикой,
изменения закона — с текущим состоянием.

Выход — документ, который юрист проходит за один проход.

**GDPR — боковая колонка, не основной режим.** Сравнение с GDPR (ст. 28, 33,
35 — DPIA) включается только когда клиент экспортный (EU-субъекты или
применимое право ЕС). Для РФ-практики основной каркас — 152-ФЗ + приказы
ФСТЭК/ФСБ/РКН.

## ⚠️ Юридический дисклеймер (канонический)

**Всё, что производит плагин, — черновик для проверки юристом.** Не юридическая
консультация, не правовое заключение, не замена юриста. Каждый документ
требует проверки квалифицированным специалистом. Источники указываются явно.

## Структура

```
privacy-legal/
├── CLAUDE.md                      # Шаблон practice profile (заполняет cold-start)
├── README.md                      # Этот файл
└── skills/
    ├── cold-start-interview/      # Интервью → пишет practice profile
    ├── customize/                 # Точечная правка профиля
    ├── matter-workspace/          # Рабочие пространства дел (для firm/мультиклиент)
    ├── dpa-review/                # Ревизия ПОРУЧЕНИЯ НА ОБРАБОТКУ ПД (ст. 6 152-ФЗ)
    ├── dsar-response/             # Запросы субъектов (ст. 14, 20, 21) + журнал
    ├── pia-generation/            # Оценка вреда (ст. 18.1), уровни защищённости
    ├── use-case-triage/           # Триаж обработки: оценка/РКН/биометрия/реестр
    ├── policy-monitor/            # Дрейф политики против проведённых оценок
    └── reg-gap-analysis/          # Законопроекты/изменения 152-ФЗ против практики
```

## Навыки

| Навык | Что делает (RU-специфика) |
|---|---|
| **cold-start-interview** | Интервью → practice profile: категория оператора (контролёр/поручитель/оба), основная обработка, интеграции, playbook поручений, эскалации, house style |
| **customize** | Точечная правка профиля без переинтервью |
| **matter-workspace** | Пространства дел для firm-практик (in-house — выключено) |
| **dpa-review** | Ревизия поручения на обработку (ст. 6): цели, перечень, действия, сроки, субпоручители с согласия оператора, ТИПЗ (ФСТЭК №21/ФСБ №378), отчётность; двунаправленный — мы поручитель или мы оператор |
| **dsar-response** | Запрос субъекта: ст. 14 (сведения об обработке), ст. 20 (исправление), ст. 21 (удаление/уничтожение), 30-дневный срок, отказ с обоснованием, запись в журнал |
| **pia-generation** | Оценка вреда субъекту (ст. 18.1 152-ФЗ, приказ РКН №274) | уровни защищённости по приказам ФСТЭК №21/ФСБ №378 | сверка с модельными условиями РКН |
| **use-case-triage** | Нужна ли оценка вреда/уведомление РКН; биометрия/БД — особый режим (ст. 10, 10.1, 11); проверка включения в Единый реестр операторов |
| **policy-monitor** | Дрейф политики против проведённых оценок и триажей: что обещает политика vs что делает практика |
| **reg-gap-analysis** | Законопроекты/изменения 152-ФЗ и КоАП ст. 13.11 против текущей практики: план ликвидации гэпов с владельцами и датами |

## Быстрый старт

```
cold-start-interview          # 2 мин quick / 10–15 мин full — пишет practice profile
use-case-triage «маркетинг хочет сегментировать клиентов по геолокации»
```

До cold-start все навыки работают в **provisional mode**: generic дефолты
(право РФ, 152-ФЗ, средний риск-аппетит) с метками `[PROVISIONAL]`.

### 1. Настройка

```
cold-start-interview
```

Приготовь: публичную политику обработки ПД (URL или файл), типовое поручение
на обработку, одну оценку вреда/документ по уровням защищённости, которым
довольны. Плюс: перечень ИСПДн/систем обработки и список целей обработки.

### 2. Триаж новой обработки или фичи

```
use-case-triage «HR-платформа хочет хранить сканы паспортов сотрудников»
```

Выход: PROCEED / ОЦЕНКА ТРЕБУЕТСЯ / ПОЛНАЯ ОЦЕНКА+УВЕДОМЛЕНИЕ РКН / STOP —
с условиями, основанием обработки (ст. 6), проверкой реестра операторов,
биометрических/специальных категорий и предложением запустить оценку
в том же диалоге.

### 3. Ревизия поручения на обработку

```
dpa-review poruchenie-vendor.pdf
```

Выход: направление определено автоматически (мы оператор — нам присылают
поручение / мы поручитель — подписываем поручение оператора), ревизия по
соответствующей половине playbook: цели, перечень ПД, действия, сроки,
субпоручители, ТИПЗ, отчётность, локализация ч. 5 ст. 18.

### 4. Ответ на запрос субъекта

```
dsar-response
```

Проводит: классификация (ст. 14 / 20 / 21 / 9 согласие) → верификация →
обход систем → анализ отказов (с обоснованием по норме) → черновик ответа +
запись в журнал запросов субъектов.

### 5. Оценка вреда для новой обработки

```
pia-generation «Система распознавания лиц на проходной»
```

Intake-вопросы → оценка вреда по ст. 18.1 (приказ РКН №274) → определение
уровня защищённости (приказы ФСТЭК №21/ФСБ №378) → сверка с модельными
условиями РКН → список условий с владельцами.

## Как плагин учится

Practice profile в `~/.hermes/legal/privacy-legal/CLAUDE.md` не статичен.
Навык сообщает, когда выход использовал дефолт, который стоит откалибровать.
`policy-monitor` ловит дрейф между политикой и практикой и предлагает правки.
Профиль можно перезаписать (`cold-start-interview --redo`), отредактировать
руками или сказать навыку: «запиши новую позицию».

## Заметки

- Ревизия поручений двунаправленная: одно и то же письмо защищает операционную
  гибкость (когда мы поручитель) и защищает данные (когда мы оператор).
  Направление определяется автоматически или спрашивается.
- Формат оценки вреда берётся из seed-документа. Без него — generic структура
  по приказу РКН №274 (формат РКН для представления оценки вреда), помеченная
  как `[дефолт — добавьте свою форму через cold-start --redo]`.
- `reg-gap-analysis` обрабатывает входящие изменения закона; `policy-monitor`
  — внутренний дрейф практики. Разные направления изменения, разные инструменты.
- Sweep `policy-monitor` требует настроенной папки outputs (задаётся на
  cold-start); без него — только direct-query режим.

## Отличия от CFL (US → РФ)

| CFL (US/EU) | Vector Legal (RU) |
|---|---|
| GDPR / CCPA / HIPAA | 152-ФЗ + приказы ФСТЭК №21, ФСБ №378, РКН (№274, №931, инциденты) |
| DPIA (ст. 35 GDPR) | Оценка вреда по ст. 18.1 152-ФЗ (приказ РКН №274); сравнение с DPIA — только для экспортных EU-клиентов |
| DPA / Art. 28 | Поручение на обработку ПД (ст. 6 152-ФЗ, письменная форма) |
| DSAR (1 месяц, GDPR) | Запрос субъекта: ст. 14/20/21 152-ФЗ, 30 дней с даты обращения |
| Breach: 72 часа (GDPR) | Уведомление РКН об инциденте: 24 ч / 48 ч / 72 ч по приказу РКН — **проверять актуальную редакцию приказа** |
| SCC | Трансграничная передача: ст. 12 152-ФЗ, уведомление РКН, приказ РКН №931 (перечень стран, обеспечение безопасности) |
| Fine up to 4% turnover | КоАП ст. 13.11: оборотные штрафы — до 18 млн ₽ за первую утечку, % выручки за повторную — **[verify — актуальная редакция КоАП]** |
| Work product (FRCP 26) | Адвокатская тайна (ст. 8 ФЗ-63) / коммерческая тайна (ФЗ-98) / честная пометка «внутренний правовой анализ» |
| CourtListener / Westlaw | pravo.gov.ru, КонсультантПлюс/Гарант через web_search + `[verify]` |

Это замены каркаса; конкретные позиции playbook — только из интервью и
seed-документов команды (как в CFL: никаких дефолтов «с потолка»).
