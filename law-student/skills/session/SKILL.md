# /session

1. Разобрать `$ARGUMENTS` — предмет и N. Не хватает — спросить:
   > Какой предмет и сколько вопросов? (напр., «Гражданское право 10»
   > или «Процесс 5 --сочинение».)
2. Загрузить `~/.hermes/legal/law-student/CLAUDE.md` → целевой экзамен,
   формат, слабые предметы.
3. Загрузить `~/.hermes/legal/law-student/study-plan.yaml`, если есть. Прочитать
   `session_history` по предмету, чтобы взвесить подтемы к слабым местам.
4. Маршрут по флагу метода:
   - `--тесты` (дефолт для экзаменационных предметов): загрузить навык
     `bar-prep-questions`, прогнать N тестовых вопросов. Применить работу с
     расхождениями (см. `## Работа с расхождениями` того навыка). Помечать
     каждый вопрос: базовая норма или специальная.
   - `--сочинение`: загрузить `bar-prep-questions`, N сочинений. Грейж по
     rubric сочинений.
   - `--flashcards`: загрузить `flashcards`, прогнать N карточек в режиме
     `--drill`.
5. Прогнать N вопросов по одному. После каждого — объяснить верно/неверно
   и пометить норму, если есть расхождение редакций/процедур.
6. В конце сессии записать результаты:
   - `study-plan.yaml` есть — append в `session_history` по схеме навыка
     `study-plan`.
   - Нет — писать в
     `~/.hermes/legal/law-student/session-history.yaml`.
7. Отчитаться:
   - Счёт: X/N (%)
   - Промахи: список с тегами подтем
   - Слабые подтемы этой сессии
   - Паттерн против прошлых сессий по предмету (если в истории 2+ прошлых)
   - Что план теперь рекомендует дальше

## Поток сессии (подробно)

1. **Подтвердить параметры:** предмет, N, метод (тесты/сочинение/карточки,
   или mix). Если предмет в слабом списке профиля — сказать: «Предмет из
   слабых — норм, это в приоритете.»
2. **Подтянуть план:** какой предмет запланирован на сегодня? Совпадает —
   отлично; не совпадает — отметить: «По плану на сегодня — [X]. Гоняем
   [этот предмет] всё равно? Он попадёт в историю сессий».
3. **Весить по истории:** подтемы прошлых промахов — выше в очереди.
4. **Прогнать вопросы по одному.** Пауза на каждом ответе; разбор после
   каждого — правильный ответ, почему остальные неверны, норма для
   запоминания.
5. **Сессия закрыта — отчёт:**

```markdown
## Сессия: [предмет], [N] вопросов

**Счёт:** [X]/[N] ([%])
**Промахи:** [подтема + что пошло не так]
**Слабые подтемы:** [2–3 подтемы сгруппированных промахов]
**Сильные подтемы:** [где уверенно]

**Паттерн против истории:** [«Сроки исковой давности мимо в 3 из 25
последних вопросов — залипло. Путь в /law-student:socratic-drill.»
или «Прогресс 40% → 70% по процессу. Плавает приказное производство.»

**Обновление плана:** [слабые подтемы — в приоритет; следующая
запланированная сессия: [дата из study-plan.yaml]]
```

6. **Записать в историю:**

```yaml
session_history:
  - date: 2026-05-08
    subject: Гражданское право
    type: bar-prep-tests  # или flashcards / essay
    n_questions: 10
    score: 6
    weak_subtopics: [sroki-davnosti, neustoika]
    method: tests
```

## Интеграция

- Результаты идут в `study-plan.yaml` → `session_history` (схема — навык
  `study-plan`), чтобы план адаптировался: слабые подтемы повышают
  приоритет и часы предмета.
- Композиция: навык сам не генерирует вопросы — он маршрутизатор поверх
  `bar-prep-questions` и `flashcards`.

## Чего этот навык не делает

- Не заменяет предметные навыки — только запускает их сфокусированно.
- Не выносит «экзаменационный вердикт» по одной сессии — тренд виден
  по истории, не по одному срезу.
- Не даёт ответов вместо студента; по завершении отправляет в план.
