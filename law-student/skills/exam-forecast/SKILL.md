# /exam-forecast

1. Загрузить `~/.hermes/legal/law-student/CLAUDE.md` → курс, преподаватель,
   формат отчётности, программа.
2. Применить workflow ниже.
3. Принять прошлые билеты (PDF, вставка, пути). Подтвердить объём выборки.
4. Разобрать каждый билет: формат, покрытие тем, стиль вопросов, плотность
   фабул, повторяющиеся ловушки.
5. Кросс-анализ паттернов — что стабильно, что варьируется.
6. Объединить с текущей программой в прогноз: веса тем, формат,
   «любимые лошадки» преподавателя, акценты для учёбы.
7. Записать
   `~/.hermes/legal/law-student/exam-forecasts/[курс]/forecast-[ГГГГ-ММ-ДД].md`.
   Кадрировать как весовой коэффициент распределения усилий, не предсказание.

## Purpose

У каждого преподавателя — отпечатки пальцев на экзамене. Те же структуры
казусов повторяются. Те же ловушки возвращаются. Те же пропорции тем
удерживаются. Студенты с прошлыми билетами учатся умнее; без — учатся
больше. Навык анализирует твои прошлые билеты и вскрывает паттерны.

Не магия. Прогноз, не предсказание. Навык не знает, что будет на экзамене, —
он видит, что было на прошлых, и что, вероятно, повторится по текущему
покрытию программы.

## Shared guardrails (канон — practice profile)

**Reviewer note / decision tree / Destination check / Provenance /
No-silent-supplement / Currency trigger / Large input** — см.
practice profile (`~/.hermes/legal/<domain>/CLAUDE.md` → `## Shared
guardrails`, `## Outputs`). Блоки канонизируются там; если текст навыка
расходится с профилем — профиль контролирует.


## Дисциплина уверенности

- Анализ паттернов (какие темы, сколько вопросов по теме, как часто доктрина
  vs применение) — уверенно, когда билеты прямо передо мной.
- Выводы о вероятных акцентах — `[НЕУВЕРЕН]` по умолчанию: это прогнозы.
  Прямо кадрировать: «по [N] прошлым билетам [тема] встречалась в [M].
  Ближайший экзамен может на ней построиться, а может преподаватель
  ротирует — воспринимай как вес для распределения времени, не как
  предсказание.»
- Только 1–2 прошлых билета — сказать прямо: любой паттерн из одного
  билета — шум.
- Преподаватель новый (прошлых билетов нет) — навык не прогнозирует.
  Сказать так; фоллбэк — «вот что покрыто программой, учи это».

## Загрузка контекста

- `~/.hermes/legal/law-student/CLAUDE.md` → курсы, форматы отчётности,
  программа курса
- Прошлые билеты от пользователя (PDF, вставленный текст, пути)
- Опционально: программа текущего курса (для «что уже пройдено»)

**Если в билетах есть имя преподавателя, использовать его для матчинга
паттернов** (билеты того же преподавателя — самый высокий сигнал). Нет
имени — матчить по предмету и структуре. Не просить впечатать имя
вручную — брать из материалов. Пользователь сам его назовёт в разговоре —
хорошо; не выспрашивать.

## Workflow

### Шаг 1: Приём

- По какому курсу прогноз?
- Сколько прошлых билетов этого преподавателя доступно?
- Того же курса, или разных курсов того же преподавателя?
- Есть ли варианты другого формата (устные, открытые книги), отличные от
  типового формата предстоящего?
- Программа текущего курса?

Меньше 3 билетов — флаг тонкой выборки; вывод паттернов слабее.
Билеты с разных курсов — паттерны стиля переносятся (формат, баланс
доктрины/практики), предметные — нет.

### Шаг 2: Прочитать каждый билет

По каждому:

- Формат (число вопросов, объём, лимит времени, устный/письменный,
  открытые/закрытые материалы)
- Покрытие тем (что проверялось, в какой пропорции)
- Стиль вопросов (казус-споттер, глубокий по одной проблеме, доктринальное
  сочинение, короткий ответ, тесты, микс)
- Плотность фабулы (казусы, богатые фактами; разреженные факты с упором на
  доктрину; или задания без фактов вообще)
- Повторяющиеся ловушки (напр., преподаватель всегда прячет процессуальный
  вопрос в чистой на вид фабуле; всегда спрашивает исключение, а не
  правило)
- Баланс доктрины vs практики (анализ судебной практики?
  законопринуждённых позиций КС/ВС?)
- Необычные структуры (сочинение + тесты, мок-заседание, дискуссия)

### Шаг 3: Кросс-анализ

Свернуть то, что стабильно между билетами:

**Стабильные паттерны (в большинстве/всех):**
- Веса тем (напр., «обязательства и их исполнение стабильно ~30% баллов»)
- Стиль вопросов (напр., «всегда один длинный казус + два коротких
  доктринальных вопроса»)
- «Лошадки» преподавателя (напр., «всегда тестирует особые случаи даже по
  темам, слабым в курсе»)

**Вариативные (в некоторых):**
- Доктринальные сочинения («в 2 из 4 — обычно, когда семестр доходил до
  теоретических тем»)
- Открытые vs закрытые материалы
- Устные vs письменные различия

**Наблюдаемые отсутствия:**
- Темы курса, НИКОГДА не встречавшиеся в прошлых билетах — не пропускать,
  но и не взвешивать чрезмерно
- Темы прошлых билетов, которых нет в текущей программе — вероятно, не
  вернутся

### Шаг 4: Прогноз на ближайший экзамен

**Header — обязателен, первая строка прогноза — и в чате, и в файле.**
По practice profile каждый учебный выход несёт дословный header. Не
опускать, не перефразировать, не переносить:

```
УЧЕБНЫЕ ЗАМЕТКИ — НЕ ЮРИДИЧЕСКАЯ КОНСУЛЬТАЦИЯ
```

Объединить анализ паттернов с текущей программой:

```markdown
УЧЕБНЫЕ ЗАМЕТКИ — НЕ ЮРИДИЧЕСКАЯ КОНСУЛЬТАЦИЯ

# Прогноз экзамена — [курс / преподаватель] — [дата]

**Прошлых билетов проанализировано:** [N]
**Уверенность выборки:** [тонкая (<3) / умеренная (3–5) / сильная (6+)]
**Оговорки:** [напр., «один из прошлых — открытая коллоквиумная форма;
ближайший — закрытый билет. Перенос частичный.»]

---

## Веса тем (исторические)

| Тема | Вес в прошлых (средний) | В текущей программе? | Прогноз веса |
|---|---|---|---|
| [тема 1] | [%] | [да/частично/нет] | [больше / стабильно / меньше] |

## Прогноз стиля вопросов

- **Формат вероятен:** [X казусов + Y коротких + Z доктринальных]
- **Плотность фабул:** [казусы, богатые фактами / разреженные / микс]
- **Стиль задания:** [один широкий вопрос / несколько узких / подпункты]

## «Лошадки» преподавателя

- [тема A] — в [M из N] билетов. Взвешена в 3–5x своей программы.
- [тема B] — [паттерн]
- [паттерн-ловушка] — напр., «прячет процессуальный вопрос в чистой фабуле»

## Темы курса, редко попадавшие на экзамены

[список — не пропускать, но не пере-взвешивать]

## Рекомендация акцентов

По паттернам И с учётом текущей программы:

**Тяжело:** [темы-якоря — 40–50% времени]
**Умеренно:** [поддерживающие — 30–40%]
**Sanity check:** [покрытые курсом, но исторически слабо представленные —
10–20%, на всякий случай]

## [НЕУВЕРЕН — кадрирование]

Прогноз построен на [N] билетах. Преподаватели меняют акценты и ротируют
темы. Считать весовым коэффициентом распределения времени, не предсказанием.
Экзамен будет содержать сюрпризы.
```

### Шаг 5: Куда пишем

Записать в
`~/.hermes/legal/law-student/exam-forecasts/[курс]/forecast-[ГГГГ-ММ-ДД].md`.
Версировано — новый билет посреди семестра → перезапуск и append.

## Интеграция

- **outline-builder:** веса прогноза — в решения по глубине конспекта
  (глубина на тяжёлых темах)
- **flashcards:** тяжёлые по прогнозу темы — больше карточек
- **bar-prep-questions:** для экзамена на статус неприменен (там своя
  модель по перечню); exam-forecast — для внутривузовских экзаменов
- **irac-practice:** темы прогноза — предметные области для тренировочных
  казусов

## Decision tree «Что дальше?»

> **Что дальше? Выбери — и помогу:**
> 1. **Казус по тяжёлой теме** прогноза — тренировка под якоря.
> 2. **Конспект тяжёлой темы** — outline-builder с приоритетом.
> 3. **Карточки по темам-ловушкам** — на ловушки преподавателя.
> 4. **Запланировать повтор** — прогнозные веса в study-plan.
> 5. **Что-то ещё.**

## Чего этот навык не делает

- **Не предсказывает конкретные вопросы.** Прошлые билеты показывают
  паттерны, не завтрашнюю формулировку.
- **Не работает без прошлых билетов.** Нет билетов этого преподавателя —
  прогноз невозможен; фоллбэк — «вот покрытие программы, учи его».
- **Не заменяет изучение всей программы.** Прогноз — взвешивание, не
  исключение. Пропустить тему из-за низкой исторической представленности —
  так студенты обжигаются на этом.
- **Не видит изменений, о которых не знает.** Преподаватель сместил акценты
  в этом году (новый акцент в лекциях) — навык не увидит, пока не скажешь.
- **Не надёжен на 1–2 билетах.** Тонкая выборка — флаг.
