# /customize — правка IP-профиля

## Когда запускается

Пользователь хочет изменить что-то в IP-practice profile — риск-постур,
контакт эскалации, позицию по компенсации, enforcement-тактику, OSS-правила,
классы МКТУ — без перезапуска интервью и без ручной правки YAML.

## Что делать

1. **Прочитать конфиг.** `~/.hermes/legal/ip-legal/CLAUDE.md` (и
   `~/.hermes/legal/company-profile.md` уровнем выше). Если конфига нет или
   есть `[PLACEHOLDER]` — сказать:

   > Setup ещё не запускался. Сначала `cold-start-interview` — customize
   > предназначен для правки уже существующего профиля.

2. **Показать карту правок.** Секции профиля ИС, сгруппированные, текущее
   значение одной строкой:

   - **Компания** — название, индустрия, юрисдикции (РФ / Мадрид / ЕАПО /
     PCT) *(общий company-profile.md)*
   - **Практика-микс** — какие типы ИС в работе (знаки / патенты / ПМ /
     авторское право / секреты / OSS / дизайн), субфокусы
   - **Портфель** — сколько знаков/патентов/ПО для ЭВМ зарегистрировано,
     реестр в ФИПС (актуальность проверяется web_search с `[ФИПС][verify]`)
   - **Enforcement posture** — агрессивная / средняя / пассивная; что это
     значит для триажа и C&D
   - **Компенсация** — рабочий диапазон по п. 3 ст. 1252 ГК (10 000 —
     5 000 000 ₽, суд определяет по характеру нарушения —
     `[settled — подтверждено YYYY-MM-DD]`, пороги меняются — сверять);
     альтернативы: убытки (ст. 15) или двукратная стоимость права
     (п. 3 ст. 1252)
   - **Люди** — цепочка эскалаций: кто получает clearance-конфликт,
     FTO-blocker (ст. 1354 ГК — право на использование), OSS-copyleft-находку
   - **Watch-лист брендов** — monitored-знаки, cadence (в /infringement-triage
     и /portfolio: watched vs reactive)
   - **Патентный поверенный** — ФИО/фирма, договор (для заявок ст. 1349–1360 ГК
     и споров — обязательный этап; скиллы готовят только intake)
   - **OSS-политика** — разрешённые без одобрения (MIT/BSD/Apache-2.0/ISC),
     требующие одобрения (LGPL/MPL/EPL), запрещённые в SaaS (AGPL —
     network-триггер, GPL для дистрибутива; SSPL/BUSL — коммерческая оценка),
     процесс добавления зависимостей, NOTICES-файл
   - **Секреты производства** — режим ФЗ-98 (приказ, перечень, доступ) —
     для /ip-clause-review и exit-протоколов
   - **NDA triage для IP-контекстов** — нет в этом плагине; см. nda-review
     
   - **House style** — язык претензий (жёсткий/дипломатичный), формат
     триаж-memo, сохранение C&D/претензий, renewal-алерты (Telegram), что
     получает патентный поверенный
   - **Интеграции** — ФИПС/СИПН/КонсультантПлюс статусы

3. **Прочитать текущее значение выбранной секции** — процитировать.

4. **Спросить новое значение.** Одно поле за раз.

5. **Показать diff** (старое → новое) **и ждать подтверждения.**

6. **Записать** в practice profile.

7. **Показать подтверждение** + одна строка: «Изменение затронет [какие
   навыки]».

## Конвенции

- **Одно поле за правку.** «Постур агрессивный» и «обнови watched-лист» —
  два вызова.
- **Цитировать перед изменением.**
- **Diff и подтверждение.**
- **Verification log.** При изменении порога компенсации или watched-листа:
  `[YYYY-MM-DD] [поле: старое → новое] изменено [кем]`.
- **Не изменять seed documents.** Только через `--redo`.

## Типовые правки

- «Постур — агрессивный» → пересчёт триаж-порогов, C&D-шаблонов, автотриггеров.
- «ФИПС-лимит 25 К» → обновление compensation-rules в профиля.
- «Watched-лист брендов: добавить /brand» → обновление Brand protection.
- «AGPL — для внутреннего тулинга разрешить, в продукт нет» → нюанс в
  OSS-политике.
- «Новое дело → matter-workspace new <slug>» — это другой навык, не customize.

## Verification log обязательный

При изменении thresholds/политик: одна строка в
`~/.hermes/legal/ip-legal/verification-log.md` — создаёт paper trail до
reliance на последующие ревизии.
