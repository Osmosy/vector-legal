## Purpose

IP-пункты в договорах разработки, NDA, фриланс-договорах, SaaS-контрактах:
уступка прав, лицензии, права на результат, гарантии чистоты. Это узкий
ревизор: только IP-содержание, коммерческие пункты — в commercial-legal.

## Precondition

Профиль: постур по IP (когда отдаём права, когда лицензируем), какие
РИД компании особенно ценны. Плейсхолдеры → `[PROVISIONAL]` с дефолтами
охранительного постура.

## Workflow

### Шаг 1: Ориентация

Прочитать договор: тип (разработка/фриланс/лицензия/NDA/трудовой?),
стороны, предмет — что создаётся, какими РИД обрастает (код, дизайн,
ТЗ для ПМ, контент). Контекст реестровых объектов: `[ФИПС][verify]` по
зарегистрированным знакам/патентам; нормы ГК — `[КонсультантПлюс]` при
проверке в сессии, иначе `[model knowledge — verify]`; цитаты договора —
`[user provided]`.

### Шаг 2: Assignment gap check (приоритет #1)

**В договорах создания РИД главный зазор — права не переданы вообще.**
Проверить:

- Есть ли **договор об отчуждении исключительного права** (ст. 1234 ГК)
  или только «исполнитель обязуется передать» (воздух)?
- **Служебные произведения** (ст. 1295): если работа выполняется
  сотрудником, договором можно прямо закрепить служебный статус; без
  этого — права у работника (исключительное право — работодателю в
  пределах служебного задания, но «авторское право» всегда у автора)
- **Для будущих РИД** — формулировка должна покрывать результаты,
  которые возникнут (по ст. 1234 допускается отчуждение будущих прав —
  но сформулировать аккуратно)
- **Лицензия vs отчуждение:** лицензия = право использования (ст. 1235);
  отчуждение = полностью (ст. 1234). Частая ошибка: «уступаем» в
  формулировке, а по сути — неисключительная лицензия

⚠️ ASSIGNMENT GAP → это блокер: 🔴, первая строка memo, именованный
аппрувер.

### Шаг 3: Clause-by-clause

По каждому IP-пункту:

| Пункт | Что проверить | Норма |
|---|---|---|
| Уступка прав | Полнота (все РИД? будущие?), формулировка, встречное | ст. 1234 |
| Лицензии | Вид (исключительная/простая — ст. 1236), тер. права, срок, отзыв | ст. 1235-1238 |
| Сублицензирование | Разрешено? условия | ст. 1238 |
| Гарантии чистоты | Кто защищает от третьих лиц (индемнити по ИС) | ст. 1237, договорные |
| Служебные РИД | Работник/подрядчик — статус, вознаграждение | ст. 1295, 1370 |
| Доступ к исходникам | Для ПО: исходники, документация | ст. 1262, 1286 |
| Территория | Не шире ли, чем нужно | |
| Реестровые РИД | ТЗ/патенты/ПО: зарегистрирован transfer? | ст. 1232 |
| Третьи лица | Права подрядчиков на OSS/библиотеки | — (→ oss-review) |
| Конфиденциальность и ИС | КТ на ноу-хау vs передача лицензиату | ФЗ-98 |

Для каждого: позиция playbook → формулировка договора → gap → severity →
конкретная редакция.

### Шаг 4: Cross-clause consistency

- «Все права переходят» vs далее «исполнитель сохраняет право на
  портфолио» — конфликт
- Автопродление лицензии vs отсутствие механизма
- Противоречие с NDA (если есть отдельным документом)

### Шаг 5: Jurisdiction note

Договор под российским правом? Иностранное право по ИС на территории РФ
не работает автоматически (территориальность прав); для экспортных
контрактов — применимое право + регистрация в target-юрисдикциях
(Мадрид для ТЗ). Метка `[РФ фреймворк — проверить против [юрисдикция]]`.

## Redline granularity

Минимальные правки: заменить «передаёт» на «отчуждает исключительное
право в полном объёме»; добавить слово «исключительную» в лицензию и
т. п. Не переписывать раздел целиком.

## Quality checks before delivering

- Каждый gap с цитатой из договора (точная, с разделом)
- Severity по шкале с конкретикой («без передачи прав исполнитель может
  передать продукт кому угодно», «лицензия без территории — на весь мир»)
- Редакции — конкретные формулировки на русском, готовые к вставке
