# /takedown — уведомления информационным посредникам

## Instructions

1. Режим: `send` (пишем уведомление посреднику) / `receive` (получили
   уведомление) — спросить, если неочевидно
2. Загрузить профиль (постур, юрисконсульт) — `[PROVISIONAL]` при плейсхолдерах
3. Выполнить шаги режима

## Purpose

В РФ вместо DMCA — ст. 1253.1 ГК (информационные посредники) и ст. 1252:
правообладатель направляет уведомление о нарушении; посредник,
своевременно принявший необходимые меры, не несёт ответственность — но
«уведомление» должно соответствовать требованиям, иначе считается
неотправленным. Для пиратских сайтов — реестр РКН (заблокированные по
суду/внесудебно — для фильмов ст. 15.6 ФЗ-149 «антипиратский закон»).

## Jurisdiction assumption

ГК РФ + ФЗ-149 «Об информации» по умолчанию. Зарубежная площадка —
их право (DMCA для США, EUCD для ЕС) — метка `[РФ фреймворк — проверить
против [юрисдикция]]`, у площадок свои формы.

## Send mode — драфт уведомления

### Шаг 1: Определить объект

| Тип | Норма | Что прикладываем |
|---|---|---|
| Авторское право | ст. 1259, 1270 ГК | Документ о праве: депонирование, договор, публикация |
| Товарный знак | ст. 1477-1515 | Свидетельство Роспатента (№ обязателен) `[ФИПС][verify]` |
| Ноу-хау | ст. 1465+ | Режим КТ — доказательства |

### Шаг 2: Определить нарушение и его место

URL точные (страницы, не «весь сайт»), дата фиксации, скриншоты (лучше —
нотариальный протокол осмотра сайта для суда).

### Шаг 3: Fair-use gate — а вдруг это не нарушение?

Перед отправкой перепроверить: не исключение ли из исключительного права
(ст. 1274 — цитирование, учебные; ст. 1275 и др.), не истёк ли срок, не
наш ли бывший подрядчик с правом. Ложное уведомление — расходы и
репутация.

### Шаг 4: Good faith

Формулировка «добросовестного убеждения» — по-русски: «мы полагаем, что
использование не имеет правовых оснований; обладаем правами на [объект]».
По-GК: уведомление должно содержать сведения о правообладателе, объекте,
нарушении (практика информационных посредников).

### Шаг 5: Authority

Кто подписывает: правообладатель или представитель (доверенность
обязательна для юрлица через подписанта из постура). Для площадки —
указать контакт для ответа.

### Шаг 6: Draft

```markdown
УВЕДОМИЕ О НАРУШЕНИИ ИСКЛЮЧИТЕЛЬНОГО ПРАВА
(ст. 1252, 1253.1 ГК РФ)

Кому: [хостинг/площадка — юрлицо, адрес]
От: [правообладатель, ИНН, контакты]

1. Мы, [правообладатель], обладаем исключительным правом на [объект]
[документ — свидетельство № / договор].
2. На странице [URL(и)] размещён [контент], использующий [объект]
без разрешения.
3. Сведения о нарушении зафиксированы [дата, способ — скриншот,
нотариальный протокол].
4. Требуем удалить [контент] до [дата — обычно 3-7 дней].
5. Контакты для связи: [email, телефон].

[Подписант, дата]
[Приложения: правоустанавливающие документы, доказательства]
```

### Шаг 7: The loud gate before delivery

Показать целиком + подтвердить отправку (внешнее действие). Площадке
обычно есть своя форма (marketplaces: Ozon/WB, хостинги, YouTube) —
подсказать, где она, но текст готовит скилл.

### Шаг 8: Output

Файл + календарный дедлайн на реакцию посредника (обычно «своевременно»
= 1–3 дня для хостингов, по правилам конкретной площадки); напоминание.
Если проигнорировали → следующая ступень: претензия (cease-desist),
исковое заявление в СИПН/АС, обращение в РКН для включения в реестр (для
фильмов/музыки — ст. 15.6 ФЗ-149).

## Receive mode — триаж полученного уведомления

### Шаг 1: Прочитать

Кто прислал, какой объект, какое основание, что требуют, срок.

### Шаг 2: Assess

- У отправителя есть право? `[ФИПС][verify]` / депонирование / публикация
- Мы действительно используем их объект? (перепроверить на своей стороне)
- Есть ли наше основание: лицензия, цитирование, добросовестное
  использование по ГК, своё более раннее использование?

### Шаг 3: Варианты

1. **Удалить** — если используем без права; предложить заменить
2. **Ответить отказом** с обоснованием (лицензия/исключение)
3. **Переговоры** — получить лицензию (ст. 1235)
4. **Игнорировать** — риск: посредник обязан удалить при валидном
   уведомлении (наш хостинг снимет контент), возможна компенсация

Для посредника (если уведомление пришло НАМ как хостингу/площадке):
наша обязaнность — не удалить молча, а передать уведомление клиенту и
принять меры только при подтверждении (иначе — риск ответственности
перед клиентом); политика посредника должна быть описана в профиле.

### Шаг 4: Memo

```markdown
[TIER HEADER]

# Уведомление о нарушении — получено, триаж

## The notice
[От кого, объект, основание, требования, дедлайн]

## Assessment
[Их право — да/нет `[ФИПС][verify]`; наше использование — есть ли основание]

## Options
[Таблица: удалить / отказ / лицензия / переговоры / игнор — с рисками]

## Recommended
[Что делать до дедлайна; кто решает (из профиля)]
```

Каждый выход — с блоком `⚠️ Reviewer note` (источники: `[ФИПС][verify]`
по свидетельствам, `[kad.arbitr.ru][verify]` по юрлицам, тег
`[user provided]` для материалов нарушения; перед опорой — проверить
действительность свидетельства по открытому реестру).

Reviewer note + decision tree.

## Что этот навык не делает

Не отправляет/не удаляет ничего сам; не работает как DMCA-агент (нет
зарегистрированного агента в РФ — это конструкция США); не заменяет
судебную защиту.
