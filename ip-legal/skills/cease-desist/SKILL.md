# /cease-desist — претензии по ИС (send/receive)

## Instructions

1. Определить режим: `send` (пишем претензию нарушителю) или `receive`
   (трижаем входящую) — если неочевидно, спросить.
2. Загрузить `~/.hermes/legal/ip-legal/CLAUDE.md` — enforcement постур,
   эскалации, контакт поверенного. Плейсхолдеры → `[PROVISIONAL]` на
   дефолтном постуре «средняя жёсткость»
3. Выполнить шаги режима ниже; выход — черновик или triage memo.

## Purpose

Претензии по ИС в РФ: специфика — досудебный порядок фактически
обязателен для взыскания компенсаций в практике (и прямо предусмотрен для
исключительных прав — ст. 1252 ГК: претензия/уведомление перед иском по
возможности; формально для компенсации не требуется, но суды ждут),
компетенция: СИПН — для споров о признании прав и по товарным знакам в
ряде составов, общие/арбитражные суды — в остальных. Претензия — не
формальность: она фиксирует позицию и стартует сроки.

## Jurisdiction assumption

По умолчанию — ГК РФ ч. 4. Зарубежное право — `[РФ фреймворк — проверить
против [юрисдикция]]` + рекомендация поверенного target-страны.

## Send mode — драфт претензии

### Шаг 1: Определить право

| Тип | Нормы |
|---|---|
| Товарный знак | ст. 1477-1515 ГК, ст. 1515 — контрафакт |
| Авторские права | ст. 1259-1302 ГК, ст. 1301 — компенсация |
| Смежные права | ст. 1309-1311 ГК |
| Изобретение/ПМ/ПО | ст. 1350-1407, ст. 1406.1 |
| Промышленный образец | ст. 1352 ГК |

Проверить, действительно ли у компании это право: документ (свидетельство
Роспатента `[ФИПС][verify]`, договор отчуждения, лицензия с правом на
подачу претензий). **Без документа о праве — стоп, сначала юрист.**

### Шаг 2: Определить нарушение

Факты: что где используется, с какой даты, скриншоты/URL, дата фиксации.
Для ТЗ — сходство до степени смешения; для авторских — копирование.
Для патента — **состав карта изобретения** (признак ↔ элемент продукта) —
это работа поверенного; скилл только организует входные данные.

### Шаг 3: Определить отношения

- Контрагент по договору? (тогда — не претензия по ИС, а договорный спор +
  ip-clause-review)
- Сублицензиат? Какая лицензия, что разрешено?
- Сторонний нарушитель?
- Для сайта/хостинга — takedown-режим (отдельный навык `takedown`)

### Шаг 4: Определить требование

Варианты ст. 1252 ГК:
- **Прекращение нарушения** — изъятие контрафакта
- **Компенсация** — п. 3 ст. 1252: от 10 000 до 5 000 000 руб. по
  усмотрению суда, или двойная стоимость права использования,
  или двойная стоимость контрафакта `[settled — но суммы меняются, verify]`
- **Убытки** — вместо компенсации (сложнее доказать размер)
- **Публикация решения** о нарушении

Требование формулируется из постура профиля: агрессивная = всё сразу;
средняя = стоп + компенсация (или «готовы обсудить лицензию»); пассивная
= только стоп.

### Шаг 5: Калибровать по постуру

Жёсткость, срок реакции, подписант (директор/юрист/поверенный), канал.

### Шаг 5.5: Counterparty diligence — REQUIRED PRECONDITION

**До драфта — проверить контрагента и показать результат пользователю.**
Не условно «если контрагент большой»: каждая претензия несёт встречную
экспозицию (respondent может подать иск о признании права отсутствующим —
п. 1 ст. 1252 ГК, или взыскать расходы по ст. 100/110 АПК/ГПК в своей
юрисдикции-выборе). Скилл не драфтит C&D, пока пользователь не увидел
diligence и не подтвердил, что идёт в бой именно с этим контрагентом.

Собрать и показать одним блоком (для визы пользователя):

- **Юрлицо** — точное фирменное наименование (ЕГРЮЛ `[egrul.nalog.ru][verify]`),
  ОГРН/ИНН, адрес, директор, учредители, недостоверность записей. Их
  зарегистрированные знаки/патенты в ФИПС в смежных классах МКТУ.
- **Масштаб и ресурсы** — headcount (LinkedIn/сайт/пресса), выручка (Sparks/
  Checko/Kontur — free-фрагменты), материнская компания. Если не определить —
  честно сказать.
- **Портфель ИС** — их знаки/патенты в классах, куда наша претензия может
  задеть их интересы; их регистрируемость и потенциал встречных заявок.
- **Судебная история** — kad.arbitr.ru: споры по ИС, СИПН-практики
  (защищаются ли они сами — DJ-претендент?), ФССП-исполнения.
- **Внешние юристы** — кто представляет в судах (из судебных актов).
- **DJ/exposure risk** — крупный контрагент может забрать спор в удобный
  форум и с большей командой; активный правообладатель может оспорить
  НАШ знак (встречное требование о досрочном прекращении ст. 1486 ГК —
  их шанс при нашем неиспользовании ≥3 лет).
- **Теневые риски** — не является ли их «нарушение» пародией/критикой
  (ст. 1259 п. 6 — свобода творчества, ст. 152.1, 1224), партийным
  использованием, законным parallel import.

Если по любому пункту `[SME VERIFY]` — пометка «не подтверждено из открытых
источников» не приравнивается к «не проблема».

`vector-check` (commercial-legal) если установлен, иначе web_search по
ЕГРЮЛ + ФИПС + kad.arbitr с `[verify]` на каждом факте.

Перед отправкой — показать полный текст + явное подтверждение:
«Отправить? Это внешнее действие и фиксация нашей позиции. Отправку
делает [подписант] через [канал]». Плагин не отправляет.

## Receive mode — триаж входящей претензии

### Шаг 1: Прочитать

Кто прислал, какое право, какие факты, какие требования, дедлайн.

### Шаг 2: Оценить утверждение

- Действительно ли у отправителя право? `[ФИПС][verify]` — их знак
  существует, действующий, на однородные товары?
- Есть ли факт нарушения? Сходство до степени смешения? — скрин по
  факторам (как в clearance)

### Шаг 3: Оценить нашу экспозицию

- Наши товары/услуги пересекаются с их классами?
- Сколько мы «наиграли»: масштаб использования, даты
- Встречные аргументы: наше более раннее использование (prior use) —
  ст. 1252 п. 1 (разумность), их неиспользование (ст. 1486),
  ничтожность их прав на часть классов, добросовестность их заявки

### Шаг 4: Опции

1. **Игнорировать** — не рекомендуется без анализа; риск СИПН/АС,
   компенсация up to 5 млн
2. **Ответить с отказом** + встречные аргументы
3. **Переговоры** — лицензия по ст. 1235+ (платная/безвозмездная)
4. **Прекратить использование** и договориться о периоде вывода
5. **Готовиться к спору** — СИПН/АС; поверенный обязателен

Рекомендация — по постуру и позициям, решение — юрист.

### Шаг 5: Deadline triage

Сроки: дедлайн в претензии (если есть); судебные сроки (для подачи
встречных — обычно 1-2 месяца с момента получения; для отзывов —
по АПК/ГПК). Крайняя дата календарём.

### Шаг 6: Triage memo

```markdown
[TIER HEADER]

# Входящая претензия по ИС — триаж

## Претензия
[От кого, право, факты, требования, дедлайн]

## Оценка утверждения
[Их право — есть/нет/спорное `[ФИПС][verify]`; нарушение — вероятное/нет]

## Наша экспозиция
[Масштаб, риски компенсации (вилка ст. 1252 п. 3), встречные аргументы]

## Опции и рекомендация
[Таблица с плюсами/минусами; рекомендуемый путь]

## Дедлайн и следующий шаг
[Дата, что до неё успеть — поверенный, оверрайды, переговоры]
```

Reviewer note + decision tree (ответить / лицензия / эскалировать /
поверенный / другое).

## Что этот навык не делает

Не отправляет претензии; не ведёт судебные дела (СИПН — через поверенных);
не оценивает патенты без составов; не заменяет vector-check по
контрагенту.
