## Purpose

OSS-лицензии — не «бесплатно»: copyleft может обязать открыть исходники
всего продукта, AGPL триггерится по сети даже в SaaS, non-OSI лицензии
(SSPL/BUSL) запрещают конкурентное использование. Ревизия — до продакшена,
не после.

## Precondition

Профиль: `## OSS-политика` — списки лицензий, процесс добавления
зависимостей, хранилище NOTICES.

## Workflow

### Шаг 1: Что ревизуем?

1. **Список зависимостей** — package.json / requirements.txt / go.mod /
   SBOM (SPDX/CycloneDX) / lockfile
2. **Одна библиотека** — пакет, который добавляем
3. **Наш код outbound** — хотим опенсорсить, проверить встроенное

### Шаг 2: Модель деплоя (ключевой вход!)

> Как деплоим?
> 1. **SaaS / hosted** — пользователи через сеть; ничего не отгружается
> 2. **Distribution** — отгружаем бинарь (десктоп, мобильное, CLI, on-prem)
> 3. **Internal only** — только внутри
> 4. **Embedded/firmware** — в устройстве

| Деплой | Критичные лицензии |
|---|---|
| SaaS | **AGPL (network-триггер)**, SSPL/BUSL/Elastic (запрет конкурентного SaaS), permissive attribution |
| Distribution | GPL, LGPL, MPL, EPL — триггер на дистрибуции; attribution |
| Internal | Копилефт обычно не триггерится (нет дистрибуции); AGPL всё равно триггерится, если внешний пользователь ходит по сети |
| Embedded | GPL особенно сложен (source disclosure + installation info) — планировать до отгрузки |

Фиксировать модель деплоя в мемо — один список по «SaaS» vs
«distribution» даёт разные ответы.

### Шаг 3: Классификация каждого пакета

Читать текст лицензии, не только метаданные (файл LICENSE может лгать).
Бакеты:

| Бакет | Примеры | Обязательности |
|---|---|---|
| **Permissive** | MIT, BSD-2/3, Apache-2.0, ISC | Атрибуция, сохранение текста; Apache-2.0 — patent grant + NOTICE |
| **Weak copyleft** | LGPL-2.1/3.0, MPL-2.0, EPL, CDDL | Раскрытие изменений на уровне файла/библиотеки; правила линковки |
| **Strong copyleft** | GPL-2.0/3.0, AGPL-3.0 | Широкое раскрытие; AGPL — и по сети |
| **Public domain** | CC0, Unlicense, WTFPL | Обычно без обязательств |
| **Non-OSI source-available** | SSPL, BUSL, Elastic, Commons Clause | Не OSS; запреты коммерческого/конкурентного использования |
| **Unknown/custom** | нет LICENSE, конфликт | СТОП — не считать permissive по умолчанию |

Флагнуть: dual-license (какую из них выбираем?), deprecated, пакеты,
у которых внутри дерева copyleft-зависимости, недавние смены лицензии
(Redis/MongoDB/Elastic — проверить версию!).

### Шаг 4: Obligations → модель деплоя

```markdown
### [package@version] — [License]
**Классификация:** [Permissive / Weak / Strong / Non-OSI / Unknown]
**Обязательства для нашего деплоя ([SaaS/…]):**
- [ ] [Конкретное: атрибуция в NOTICES / исходники модификаций /
  AGPL-триггер по сети]
**Риск:** 🔴/🟠/🟡/🟢
**Рекомендация:** [соблюдать / заменить на X / удалить / одобрение юриста
/ коммерческая лицензия]
```

**Как потребляется copyleft (критично для severity):**
- **Статическая линковка** → copyleft скорее триггерится
- **Динамическая / отдельный процесс IPC** → разделимо, LGPL обычно ок,
  GPL спорно
- **Network API** → для большинства — нет; для **AGPL — да, даже через
  микросервисный шлюз** (AGPL сеть = дистрибуция)
- **MPL — file-scope** — только изменённые файлы

«LGPL — слабый copyleft» без анализа линковки — неверный ответ.
Static-linked LGPL в нашем проприетарном продукте — 🔴; dynamic — 🟢.

**Severity:**
- 🔴 Copyleft в деплое, который триггерит (GPL в distribution, AGPL в
  SaaS); non-OSI, конфликтующая с бизнес-моделью (SSPL у managed-сервиса);
  лицензия не определена и пакет load-bearing
- 🟠 Weak copyleft без подготовки (NOTICE, раскрытие файлов); dual-license
  с неоднозначным выбором; LICENSE ≠ заголовкам
- 🟡 Permissive без атрибуции в build; транзитивный copyleft в спорной
  позиции
- 🟢 Permissive, обязательства выполнены; copyleft вне триггера

### Шаг 5: Failure modes

- AGPL-компонент в SaaS без осознания network-триггера
- LICENSE-файл говорит MIT, заголовки файлов — GPL
- Пакет сменил лицензию (Redis → RSAL/SSPL; Terraform → BUSL) — pinned
  версия уже не та
- Скопированный код из StackOverflow с неизвестной лицензией в наш код
- GPL-шрифт/иконки в UI продукта (дистрибуция!)
- Проприетарное расширение поверх copyleft-хоста («свой плагин к GPL,
  но мы продаём»)

### Шаг 6: Outbound check (наш код наружу)

Если опенсорсим: какие встроенные зависимости, совместим ли выбранный
outbound-лиценз (GPL-код нельзя лицензировать MIT), LICENSE/NOTICE
корректны, есть ли патентные оговорки.

## RF-специфика (коротко)

- **MIT/Apache-2.0/BSD совместимы** с использованием в проприетарных
  продуктах — обязательства: сохранение копирайтов/текстов, NOTICE
  (Apache-2.0), атрибуция
- **AGPL/copyleft-вирусность для SaaS:** AGPL-3.0 §13 — network use =
  distribution: если наш SaaS использует AGPL-компонент и пользователь
  ходит по сети, мы обязаны предложить исходники *своего* стека (включая
  модификации). Для закрытого SaaS — обычно стоп или коммерческая
  лицензия
- **Copyleft-стеки:** цепочка copyleft-зависимостей внутри дерева
  превращает весь продукт в copyleft; проверять транзитивно (SBOM)
- Гражданско-правовые последствия нарушения OSS-лицензий в РФ
  устанавливаются судами через ГК (нарушение исключительного права) —
  практика по AGPL в РФ ещё формируется `[model knowledge — verify]`

**Теги источников:** лицензия каждого пакета — только по тексту,
проверенному в этой сессии (`[user provided]` для выгрузки зависимостей)
или `[web search — verify]` при сверке с репозиторием пакета; никогда
не «помню, что это MIT».

## Close

1. **Заменить пакеты** — список альтернативы
2. **NOTICES-файл** — сгенерить черновик
3. **Эскалировать** 🔴 аппруверу
4. **Коммерческая лицензия** — драфт запроса вендору
5. **Другое**

## Чего не делает

Не проверяет безопасность пакетов (CVE — не здесь), не заменяет SBOM-
инструменты; лицензии — только по тексту в этой сессии или `[user provided]`.
