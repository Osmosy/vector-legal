# AI Governance Counsel — управление рисками ИИ (Vector Legal)

Адаптация [claude-for-legal/ai-governance-legal](https://github.com/anthropics/claude-for-legal)
(Anthropic, Apache-2.0) под право РФ и Hermes Agent.

## Что это

Управление ИИ-системами компании как юристом, а не AI-инженером: реестр
систем (роль и уровень риска — **по каждой системе**, не по компании),
триаж новых use-case'ов против red lines профиля, оценка воздействия,
ревизия вендорских ИИ-соглашений, мониторинг политики. Выход — memo с
уровнем риска, классификацией и маршрутом одобрения.

## ⚠️ Юридический дисклеймер (канонический)

**Всё, что производит плагин, — черновик для проверки юристом.** Не юридическая
консультация, не правовое заключение, не замена юриста. Классификации
систем и выводы по нормам требуют проверки квалифицированным специалистом.
Источники указываются явно.

## Структура

```
ai-governance-legal/
├── CLAUDE.md                  # Шаблон practice profile (заполняет cold-start)
├── README.md                  # Этот файл
└── skills/
    ├── cold-start-interview/  # Интервью → пишет practice profile
    ├── customize/             # Точечная правка профиля
    ├── matter-workspace/      # Рабочие пространства дел (для firm/мультиклиент)
    ├── ai-inventory/          # Реестр ИИ-систем: роль + tier по каждой системе
    ├── use-case-triage/       # Новый use-case → GREEN/AMBER/RED против профиля
    ├── aia-generation/        # Оценка воздействия (аналог DPIA для ИИ)
    ├── vendor-ai-review/      # Ревизия ИИ-соглашений с вендорами
    ├── policy-monitor/        # Мониторинг ИИ-политики на пробелы
    ├── policy-starter/        # Черновик ИИ-политики с нуля
    └── reg-gap-analysis/      # Gap-анализ нового НПА против текущего состояния
```

## Быстрый старт

```
cold-start-interview    # 10–15 мин — пишет practice profile
ai-inventory list       # реестр ИИ-систем
use-case-triage <описание use-case>
```

До cold-start все навыки работают в **provisional mode**: generic дефолты
(право РФ, средний риск-аппетит) с меткой `[PROVISIONAL]`.

## Practice profile

Конфигурация живёт в `~/.hermes/legal/ai-governance-legal/CLAUDE.md`
(шаблон — `CLAUDE.md` в корне плагина). Профиль содержит: роль и
регуляторный профиль компании, реестр use-case'ов с red lines,
иерархию одобрений (governance tiers), путь к реестру систем
`ai-systems.yaml`, house style assessing'а.

### Право Российской Федерации (базовые замены против EU/US-версии)

| CFL (EU/US) | Vector Legal (RU) |
|---|---|
| EU AI Act — основной каркас (риск-категории) | РФ: специализированного ИИ-закона нет → **ФЗ-123 от 24.04.2020** об экспериментальном правовом режиме (ЭПР) для разработки/внедрения ИИ в Москве — *пилотный, статус и продление проверять `[verify]`*; обычный режим — общие законы (152-ФЗ, ГК, отраслевые) |
| Регистр высокорисковых систем (ст. 6, Приложение III) | Реестр ведётся внутри компании; для систем в ЭПР — включение в реестр ЭПР (Москва). ГОСТ Р 59276-2020 «Системы искусственного интеллекта. Способы обеспечения доверия» — добровольный стандарт, частично применяется в гос-закупках |
| GPAI (ст. 51-55) | Для экспортных систем — EU AI Act: GPAI-классификация *(с 02.08.2025 обязательства по GPAI — `[verify]` актуальные даты применения)* |
| Директива о прозрачности платформ / DSA | РФ: Закон о платформенной экономике (проект), 152-ФЗ, ЗоЗПП; маркировка ИИ-контента — экспериментальные режимы `[verify]` |
| NIST AI RMF / ISO/IEC 42001 | **ГОСТ Р ИСО/МЭК 23894** (риск-менеджмент ИИ), ГОСТ Р 59276-2020 (доверие) — добровольные, но используются в тендерах и due diligence |
| Colorado AI Act / BIPA | Для экспорта в США — по запросу; в РФ-профиле не по умолчанию |

**Ключевая рамка ролей CFL сохранена** (она юрисдикция-нейтральна и нужна для
EU AI Act): провайдер / деплойер / импортёр / дистрибьютор / уполномоченный
представитель / производитель продукта — оценивается **по каждой системе**.
Одна компания может быть провайдером системы A и деплойером системы B —
«роль компании» как единая метка даёт неверные ответы.

**152-ФЗ сквозной:** почти каждый ИИ-use-case обрабатывает ПДн →
согласие субъекта, локализация баз (ч. 5 ст. 18), поручение на обработку
(ст. 6), ТИПЗ (приказ ФСТЭК №21) для ГИС, трансграничная передача
(ст. 12, приказ РКН №931). Оценку воздействия для ИИ-систем см. в
`aia-generation`.

## Provisional mode

До заполнения профиля: право РФ, средний риск-аппетит, классификация систем
только по первым принципам (152-ФЗ применим всегда, где есть ПДн; ЭПР —
только по фактическому включению). Каждый выход помечается
`[PROVISIONAL — запусти cold-start-interview для калибровки]`.

## Отличия от CFL

1. Право РФ вместо EU AI Act как основной каркас (таблица выше); EU AI Act
   сохранён как вторичный модуль для экспортных систем
2. Пути: `~/.hermes/legal/` вместо `~/.claude/plugins/config/`
3. Источники: КонсультантПлюс/Гарант через web_search с тегом `[verify]`;
   НПА — pravo.gov.ru; официального MCP для российских ИИ-реестров нет
4. Slack-уведомления → Telegram через Hermes gateway
