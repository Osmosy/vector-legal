# /use-case-triage — триаж ИИ-use-case

## Matter context

Проверить `## Matter workspaces` в practice profile. Если `Enabled: ✗`
(дефолт in-house) — работать на practice-level. Если включено — спросить,
для какого дела. Выходы в `~/.hermes/legal/ai-governance-legal/matters/<slug>/`.
Чужие дела не читать без `Cross-matter context: on`.

---

## Purpose

Новое применение ИИ приходит к юристу вопросом вроде «можем ли мы
использовать ChatGPT для разбора заявок клиентов?» Задача навыка — быстро
отсортировать: это разрешено по политике (GREEN), требует условий
(AMBER), требует полноценной оценки (route to aia-generation) или это
red line (RED).

**Цель:** типовые запросы — минута; серьёзные — сразу в нужный процесс,
без самодеятельного «решения».

## Сначала — практика-profile

**Загрузить** `~/.hermes/legal/ai-governance-legal/CLAUDE.md`. Если есть
`[PLACEHOLDER]` — остановиться:

> Плагин не настроен. Запусти `cold-start-interview` — без профиля триаж
> будет generic. Могу пройти в provisional-режиме с меткой
> `[PROVISIONAL]` — скажи «provisional».

### Provisional mode

Generic дефолты: право РФ, средний риск-аппетит. Red lines — по первым
принципам 152-ФЗ и трудового права; классификация — по EU Act только при
eu_nexus. Каждый выход — `[PROVISIONAL — запусти cold-start-interview для
калибровки]`. GREEN в provisional не выдаётся (нет реестра, нет
проверенных юристом позиций).

## Процесс триажа

### Шаг 1: Понять use case

> Что именно делаем? Кто пользователь? Вход — что? Выход — что? Какие
> данные (есть ли ПДн)? Кто принимает решения на основании выхода?

Зафиксировать одной формулировкой: **[Система] делает [действие] на
[данные] для [пользователь] affecting [кто затронут]**.

### Шаг 2: Реестр use-case'ов

Проверить `## Use case registry` в профиле:

- **Точное совпадение** → вернуть запись: статус, условия, red line-причина
- **Частичное совпадение** → вернуть ближайшие записи + флаг «новый
  вариант, требует решения»
- **Нет совпадения** → продолжить и предложить добавить в реестр (шаг 6)

### Атрибуция источников

При любой ссылке на регулирование — тег происхождения:
- `[pravo.gov.ru]` / `[КонсультантПлюс]` — реально из этого источника в этой сессии
- `[user provided]` — пользователь вставил
- `[model knowledge — verify]` — всё остальное (по умолчанию)

Не повышать тег из-за «цитата выглядит правильно». Честная пометка
`[model knowledge — verify]` лучше уверено-неверной.

### Шаг 3: Red line check

Сверить с `### Red lines` в профиле. Попадание → **RED**, автоматическое
нет независимо от формулировки запроса. Типовые РФ red lines (заполняются
в профиле, здесь — ориентиры для интервью, не решения):

- Обработка особых категорий ПДн ИИ-системой без правовой основы (ст. 10 152-ФЗ)
- Автоматическое принятие решений, порождающих юр. последствия для
  работника, без согласия и без человеческого участия — ст. 16 ТК
  (трудовые отношения), общие нормы ГК; для экспорта — ст. 22 EU AI Act
- Скрытая идентификация/биометрия без согласия (152-ФЗ ст. 9, 11)
- Передача ПДн вендору без поручения на обработку (ч. 3 ст. 6) и
  трансграничной проверки (ст. 12)

Встретилось условие, которого нет в red lines профиля, но похоже по
тяжести? → остановить и спросить юриста, не «выводить» красную линию
самостоятельно.

### Шаг 4: Классификация и выход

Уровень риска:

| Признак | Транспорт | Выход |
|---|---|---|
| Обрабатывает consequential-решения о людях (найм, кредиты, доступ к услугам), биометрия, скоринг | Высокий | route to aia-generation + юрист |
| Персональные данные клиентов/сотрудников, не consequential | Повышенный | юрист + ПДн-оценка (см. профиль) |
| Внутренние инструменты, черновики, без ПДн | Стандартный | по governance tier профиля |
| Попал red line или близко к нему | RED | юридический стоп |

**Формат выхода:**

```markdown
[TIER HEADER — по профилю]

## Триаж use-case: [название]

**Вердикт:** [Стандартный / Повышенный / Высокий / RED]
**Совпадение с реестром:** [id / нет — новый / частичное]

### Что это
[Одна-две строки.]

### Почему такой вердикт
- [Фактор — норма — источник-тег]

### Что нужно для [Стандартный/Повышенный]
- [Условие 1 — напр., поручение на обработку для вендора, ч. 3 ст. 6 152-ФЗ]
- [Условие 2]

### Следующий шаг
[Путь по governance tier — кто одобряет, что проверить]
```

**Строка обязательна:** «Вердикт — рекомендация по профилю, не правовой
вывод».

### Шаг 5: Кросс-плагинные эскалации

- Основание обработки, согласие, локализация → `privacy-legal`
- Вендорский ИИ уже у контрактов → `vendor-ai-review` (этот же плагин)
- Договор с вендором (не ИИ-пункты) → `commercial-legal / vendor-agreement-review`
- Товарный знак для нового AI-продукта → `ip-legal / clearance`

### Шаг 6: Обновление реестра

Предложить: «Добавить в `Use case registry` с этим статусом?» — да →
записать. Не добавлять до финального одобрения юристом, если вердикт
Повышенный или Высокий.

## Batch triage

Несколько use-case'ов за раз: таблица с колонками use-case → вердикт →
ключевой фактор. Один абзац после таблицы: паттерны (много ПДн без основы?)
и общий рекомендательный шаг.

## Reviewer note

Каждый выход — с блоком `⚠️ Reviewer note` по формату practice profile:
источники (что проверено / что `[model knowledge — verify]`), покрытие
(какие реестры прочитаны), флаги, перед опорой на вывод.

## Пограничные случаи и failure modes

- **«Это просто эксперимент»** — эксперимент с данными клиентов = та же
  обработка ПДн. Триаж по полному процессу
- **«Вендор сказал, что GDPR-compliant»** — это не 152-ФЗ. GDPR-комплаенс
  не покрывает локализацию (ч. 5 ст. 18) и поручение по российскому праву
- **«Мы не обрабатываем ПДн»** — имена в промптах, e-mail, логи — это ПДн.
  Проверить входные данные по описанию use-case, не по уверению
  пользователя; расхождение — флагнуть
- **Два use-case'а в одном запросе** — триажить отдельно
- **Внутренний инструмент выезжает наружу** — перепроверить вердикт
  («внутренние черновики» → «клиентский сервис» меняет класс)

## Decision tree после триажа

> **Что дальше? Выбери, и я помогу:**
> 1. **AIA** — оценка воздействия `aia-generation`
> 2. **Реестр** — добавить use-case с этим вердиктом
> 3. **Эскалировать** — короткая эскалация аппруверу из профиля
> 4. **Дособрать факты** — 2–3 открытых вопроса
> 5. **Другое**

## Что этот навык не делает

- Не выдаёт GREEN без заполненного профиля и реестра
- Не заменяет AIA для consequential-решений
- Не делает выводов по зарубежной юрисдикции без eu_nexus-флага и
  соответствующего фреймворка
- Не изменяет контракт вендора — это `vendor-ai-review`
