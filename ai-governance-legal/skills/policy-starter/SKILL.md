# /policy-starter — черновик ИИ-политики

## Matter context

Проверить `## Matter workspaces` в practice profile; если включено —
спросить для какого дела.

---

## Purpose

У компании нет ИИ-политики, или политика на одну страницу и не отвечает
на реальные вопросы команды. Цель — не «идеальная политика», а рабочий
документ, который команда будет открывать и по которому юрист сможет
принимать решения. Draft для проверки юристом — не финал.

## Сначала прочитать профиль

`~/.hermes/legal/ai-governance-legal/CLAUDE.md` — реестр use-case'ов,
red lines, governance tiers, роли (кто юрист / не-юрист), интеграции.
Плейсхолдеры → «профиль не настроен; политика будет generic — запусти
`cold-start-interview` или скажи «provisional»».

## Scope-интервью (ДО драфта)

Спросить:

1. **Для кого:** вся компания / ИТ / отдельная команда? Язык — русский?
2. **Формат:** полноценный документ / одностраничник / wiki?
3. **Режим использования ИИ сегодня:** что уже реально используется
   (ChatGPT, Copilot, внутренние системы из ai-systems.yaml)?
4. **ПДн:** какие данные реально ходят в ИИ? Есть ли вектор для
   сотрудников «не вставлять клиентские данные»?
5. **Требуемые каркасы:** нужен ли якорь на ГОСТ Р 59276-2020 (для
   тендеров) или ГОСТ Р ИСО/МЭК 23894 (процесс рисков)? Или без ГОСТ —
   просто нормы 152-ФЗ?
6. **Кто подписывает:** CEO / юрист / комплаенс? Кто отвечает на вопросы
   команды?
7. **Где жить будет:** файл/Confluence/Nextcloud? Кто вносит правки?

## Sourcing каркаса

Не выдумывать «лучшие практики» с потолка. Источники каркаса по убыванию:

1. **Реестр use-case'ов и red lines** из профиля — политика описывает
   **их**, не абстракцию
2.152-ФЗ (обработка ПДн) — ст. 6 основания, ст. 9 согласие, ч. 5 ст. 18
   локализация, ч. 3 ст. 6 поручения, ст. 12 трансграничка, приказ
   РКН №931 — где применимо, с тегом `[pravo.gov.ru]` при подтверждении
3. **ГОСТ Р 59276-2020 «Системы ИИ. Способы обеспечения доверия»** —
   добровольный; используется как каркас «способы обеспечения доверия»,
   если user решил (в тендерах встречается)
4. **ГОСТ Р ИСО/МЭК 23894 (риск-менеджмент ИИ)** — добровольный процессный
   каркас; структура рисков может повторять его логику
5. **EU AI Act** — только если eu_nexus систем; иначе не упоминать
   в политике для РФ-команды
6. **Отраслевики:** если компания в финансовом секторе — ЦБ-нормативы;
   в медицине — свои. Только по факту, не «на всякий случай»

Каждый пункт политики с тегом источника:
`[pravo.gov.ru]`, `[ГОСТ Р 59276-2020]`, `[user provided]`,
`[model knowledge — verify]`, `[КонсультантПлюс]`.

### Executive summary

3–5 строк: что разрешено по умолчанию, что запрещено, куда задавать вопросы.

### Разделы (типовой каркас, калибровать по scope-интервью)

1. **Цели и охват** — для кого, что покрывается
2. **Принципы** — краткие (законность, минимизация ПДн, прозрачность,
   человеческий надзор)
3. **Разрешённое по умолчанию** — типы задач, где ИИ можно без одобрения
4. **Требующие одобрения** — с governance tier профиля; маршрут одобрения
5. **Запрещённое** — red lines из профиля дословно
6. **Персональные данные** — практические правила: что вставлять нельзя,
   поручения, основание обработки; отсылка к privacy-legal на детали
7. **Вендорские ИИ-инструменты** — процесс закупки, ревизия
   (`vendor-ai-review`), субпроцессоры, обучение на данных
8. **Реестр систем** — ссылка на ai-systems.yaml; кто поддерживает
9. **Инциденты** — куда сообщать при утечке/ошибке; уведомление РКН
   (ч. 3.1 ст. 21 152-ФЗ) через privacy-legal
10. **Ответственность** — кто отвечает за соблюдение (роли, не имена)
11. **Пересмотр** — периодичность, триггеры (новый НПА, новая система)
12. **Глоссарий** — термины на русском, без англицизмов сверх необходимости

## Don'ts

- Не копировать политику «среднего западного стартапа» — каркас только
  из реестров профиля и подтверждённых источников
- Не писать политику, противоречащую red lines профиля
- Не делать текст длиннее, чем реально будут читать (лимит — не жёсткий,
  но спрашивать пользователя)
- Не вводить юр. обязательств, которые компания не сможет исполнять
  (например, локализация без реальной возможности её обеспечить)
- Не оставлять `[PLACEHOLDER]` в финальном драфте без пометки
  «заполнить перед подписанием»

## Handoffs

- Политика готова → `customize` профиля: «связать red lines с политикой»
- Появился новый НПА → `reg-gap-analysis`
- Мониторинг политики → `policy-monitor`
- Вендорский контракт под политику → `vendor-ai-review`

## Output scope

Один документ за раз. Если пользователь просит «политика + инструкция +
презентация» — политика первична, остальные — после её проверки юристом.
