# Шаблон дашборда (Dashboard Template)

*На который ссылается guardrail «Dashboard offer». Дашборды простые и
последовательные — ценность в скорости понимания, не в визуальном полирове.*

## Структура (сверху вниз)

1. **Заголовок и метаданные.** Что это, когда сгенерировано, что покрывает.
   Одна строка.
2. **Summary stats.** Цветные счётчики, которые важны. «40 находок: 🔴 3
   блокирующих · 🟠 8 высоких · 🟡 15 средних · 🟢 14 низких — 6 дедлайнов на
   этой неделе». Самая ценная строка — делается сканируемой.
3. **The reviewer note.** Тот же one-block формат, что и у любого выхода.
   Источники, охват, флаги, «перед опорой на вывод». Дашборды не пропускают
   safety-метаданные.
4. **Графики.** Максимум один-два. Выбирать по форме данных:
   - **Распределение рисков** (bar): счётчики по severity. Для находок, issues, флагов.
   - **Разбивка по категориям** (pie / stacked bar): счётчики по типу. Для OSS-лицензий, типов договоров, категорий дел.
   - **Таймлайн** (Gantt-lite или сортированная таблица): даты по порядку. Для реестров продлений, трекеров дедлайнов, closing checklists.
   - Больше двух графиков нельзя. Дашборд с пятью графиками — это отчёт,
     а отчёты читаются хуже таблицы.
5. **Таблица.** Сортируемая, фильтруемая, цветовая кодировка по severity/
   status. Колонки — из исходного выхода, обрезанные до экрана.
   Колонку «детали/заметки» — последней (она и обрезается).
6. **Decision tree.** Те же опции, что в текстовом выходе. «Что дальше?»

## Рендеринг по поверхности

- **Hermes Web / Claude Desktop:** HTML-артефакт. Самодостаточный, один
  файл, inline CSS. Без внешних зависимостей, без CDN, без npm. Таблицы:
  HTML `<table>` с `data-sort` и маленьким inline JS-сортером. Графики:
  inline SVG или Unicode-блоки для bar. JS минимален — сортировка и
  фильтрация, больше ничего.
- **Hermes CLI:** тот же HTML в outputs-каталог плагина
  (`~/.hermes/legal/<plugin>/outputs/dashboard-<тема>-<дата>.html`) + ссылка
  пользователю. Плюс markdown-версия с Unicode-блоками для summary stats,
  чтобы форму было видно прямо в терминале.
- **Excel (где уместно):** для `tabular-review`, `renewal-tracker`,
  `entity-compliance` и всего, что уходит на встречу или не-техническому
  стейкхолдеру. Использовать существующую Excel-спеку + защиту от
  formula-injection.
- **Telegram (gateway):** markdown-версия Unicode-блоков + файл HTML
  приложением при запросе. Без интерактива.

## Экранирование недоверенного ввода (применять всегда, везде)

Каждое значение, пришедшее извне сессии — поля OSS-пакетов из чужих
манифестов, текст договоров контрагента, находки diligence, имена вендоров,
описания дел, любые строки из VDR или от пользователя — **HTML-escape до
попадания в документ**. Экранировать `&`, `<`, `>`, `"`, `'` в сущности при
записи в ячейки таблиц, summary-строки, подписи графиков и tooltip'ы.
В inline JS-сортере текст ячейки — через `textContent`, никогда `innerHTML`.
В `<script>`-блоках не интерполировать недоверенные строки. URL в `href`/
`src` — со scheme-check (`http:`/`https:`/`mailto:` только). Это
HTML-эквивалент защиты Excel от formula-injection: та же угроза
(ячейка контролируется атакующим), другая поверхность исполнения —
браузерный JS вместо табличной формулы. Дашборд, который ревьюер открывает
в браузере, — trust boundary; относиться как к границе.

## Что делать

- Дашборд offer-ится, когда выход data-heavy (> ~10 строк таблицы, или
  любой портфель/реестр/трекер). Не строить без запроса — сделать
  конкретное предложение рядом с decision tree.
- Test: «читатель за 3 секунды видит форму данных?» Если нет — переработать.
