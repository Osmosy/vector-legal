# CONNECTORS — добавление коннектора

Плагины Vector Legal на пике возможностей, когда подключены к авторитетным
источникам. Если вы разрабатываете или эксплуатируете юридический источник
данных, research-tool, CLM, DMS, e-discovery-платформу или систему управления
практикой — мы хотим видеть ваш MCP-коннектор в наборе.

## Что делает хороший юридический MCP-коннектор

- **Remote MCP server по HTTPS** с OAuth или API-key авторизацией
  (streamable HTTP или SSE transport)
- **Read-heavy инструменты** — search, fetch, list. Write-инструменты
  (создать, отправить, подать) требуют явного клиентского confirmation —
  укажите это в описаниях инструментов
- **Provenance в результатах** — возвращать источник, дату получения и
  citation-ready идентификатор. Плагины теггат каждую цитату по источнику;
  ваш коннектор должен это позволять
- **Никакого instruction-подобного контента в результатах** — плагины
  трактуют полученное как данные, не команды. Если результаты содержат
  метаданные или системные заметки — маркируйте их явно, чтобы они не
  выглядели встроенными директивами
- **Rate limits и graceful degradation** — у плагинов есть фоллбэк, когда
  коннектор не отвечает; чистая ошибка лучше таймаута

## RF-специфика (что коннекторить в первую очередь)

> инструкции подключения через `hermes mcp add`, fallback-маска.

| sudrf.ru / ГАС «Правосудие» | суды общей юрисдикции | гражданские/уголовные дела | нужен |

| ЕГРЮЛ/ЕГРИП (ФНС) | реестры юрлиц | статус, адрес, директор, учредители, ОКВЭД, капитал | нужен |
| ФССП | исполнительные производства | долги контрагентов | нужен |

Кто-то из этого — открытые API (kad.arbitr частично, pravo.gov.ru), кто-то —
парсится через web_search с `[verify]`. MCP-сервер убирает `[verify]`-налог.

## Как контрибьютить

1. Публиковать MCP-сервер, задокументировать tools, auth flow и покрытие
   данных.
2. Открыть PR, добавляющий сервер в `.mcp.json` соответствующего домена с
   URL, auth-методом и one-line описанием.
3. Отметить, для каких practice areas / плагинов он полезнее всего.
4. Мы тестируем против workflows плагина; коннекторы, прошедшие
   retrieval-quality и injection-resistance проверки, попадают в дефолтный
   `.mcp.json`; остальные документируются в README плагина.

## Какие сейчас источники (вместо `.mcp.json`)

Дефолтная интеграция сейчас — через web_search + provenance-теги:

| Источник | Заменяет | Тег provenance |
|---|---|---|
| kad.arbitr.ru | CourtListener | `[kad.arbitr.ru]` |
| sudrf.ru | CourtListener (СОЮ) | `[sudrf.ru]` |
| pravo.gov.ru | Federal Register | `[pravo.gov.ru]` |
| КонсультантПлюс (free источники) | Westlaw/Practical Law | `[КонсультантПлюс]` |
| ЕГРЮЛ | SEC EDGAR | `[egrul.nalog.ru]` |
| Федресурс | PACER-банкротства | `[fedresurs.ru]` |
| ФИПС | USPTO | `[ФИПС]` |
| regulation.gov.ru | Regulations.gov | `[regulation.gov.ru]` |

Все цитаты из них — через web_search или парсинг открытых страниц, поэтому
получают тег `[verify]` до прямой проверки. MCP-коннектор снимает налог.

## Гигиена: что НЕ коннекторить

- Источники без лицензии на программный доступ (парсинг платных баз
  нарушает тос)
- Источники, отдающие контент без provenance-полей (невозможно тегировать
  цитаты)
- Источники, смешивающие данные с инструкциями (prompt-injection риск)
