# SaaS/MSA Review — ревизия подписок на ПО и облачные услуги

## Matter context

Как в vendor-agreement-review: только для firm-практик. In-house работает на
practice-level: `~/.hermes/legal/commercial-legal/CLAUDE.md`.


---

## Shared guardrails (канон — practice profile)

**Reviewer note / decision tree / Destination check / Provenance /
No-silent-supplement / Currency trigger / Large input** — см.
practice profile (`~/.hermes/legal/<domain>/CLAUDE.md` → `## Shared

## Purpose

SaaS-подписка — это vendor-договор плюс слой специфических рисков: деньги
привязаны к Order Form, а не к телу договора; автопродление молча продлевает;
цены тихо растут; SLA обещает uptime, который нечем подкрепить; наши данные
живут на стороне вендора (152-ФЗ + локализация); выход означает миграцию
данных, о которой договор обычно не говорит.

Этот навык — **поверх** vendor-agreement-review: все проверки там применяются,
здесь только SaaS-специфика.

## Workflow

### Шаг 0: Vendor-agreement-review полностью

Прочитать договор как vendor-agreement (Step 1–4: Orient, deal-breaker,
term-by-term, redline). Это база. Затем добавить SaaS-слой ниже.

### Шаг 1: Ориентация по SaaS-специфике

| Вопрос | Ответ |
|---|---|
| Модель подписки? | SaaS / IaaS / лицензия on-prem с подпиской на поддержку |
| Цена — где? | Договор / Спецификация / Order Form / прайс-лист по ссылке |
| Автопродление? | Автоматически / по соглашению / нет. Окно отмены? |
| SLA? | % uptime, кредиты, измерение, исключения из измерений |
| ПДн у вендора? | Да — поручение (ст. 6 152-ФЗ)? Локализация? ТИПЗ? Экспорт? |
| Export/embargo? | Зоны, санкционные оговорки, блокировки по санкциям |
| Exit? | Право на выгрузку данных, формат, помощь в миграции, срок, стоимость |

### Шаг 2: SaaS-специфичные проверки (против playbook)

#### 2.1 Автопродление

**Где искать:** «Срок действия», «Продление», «Renewal».

| Что проверять | Что флагать |
|---|---|
| Автопродление по умолчанию? | Если да — окно отмены ≥ 30 дней (`[review]` если меньше) |
| Уведомление об отмене? | «За N дней до окончания периода» — N в диапазоне playbook; уведомление заказным письмом = риск пропуска, флагнуть способ |
| Повышение цены при продлении? | «Вендор может менять цены» без cap — 🔴; с уведомлением за 60+ дней и правом отказа — приемлемо |
| Претензионный срок после автопродления | Ст. 425 ГК: продление = тот же договор; спорные условия те же |

**По праву РФ:** автопродление допустимо (ст. 425 ГК), но в публичных
договорах (ст. 426) и для потребителя — проверка на ущемляющие условия. Для
гос-закупок (44-ФЗ) — автопродление обычно не работает, отдельный договор.

#### 2.2 Порядок цен и повышение

| Что проверять | Что флагать |
|---|---|
| Where's the price? | Если в Order Form — это единственная твердая цена; прайс-лист «по ссылке» может меняться молча |
| Rate protection? | «Цены фиксируются на [период]» — если нет, флаг «повышение без защиты» |
| Indexation? | Привязка к индексу — проверка формулы, порогов |
| Currency? | Если цена в USD/EUR — курсовой риск; флаг, если наш бюджет в рублях |

#### 2.3 SLA и кредиты

| Что проверять | Что флагать |
|---|---|
| Uptime % | 99.0% = 7.2 ч/мес простоя; 99.9% = 43 мин; 99.95% = 21 мин. Что нам реально нужно? |
| Измерение | Кто измеряет? Self-reported вендором = риск. Внешний монитор? |
| Кредиты (service credits) | % месячной платы за нарушение; кредиты — единственный реальный механизм, не «убытки» |
| Cumulative cap на кредиты | «Максимум X% месячной платы за год» — частый cap, обесценивающий SLA |
| Exclusions из uptime | Плановые работы, форс-мажор «по определению вендора», проблемы нашего интернета — широкий список = SLA пустое |
| Termination for chronic breach | «N нарушений SLA за период = право расторжения + pro-rata refund» —必须有, иначе SLA без enforcement |
| Критические данные | Если у вендора критический производственный процесс — «uptime 99.9% с self-report» — флаг 🟠 |

#### 2.4 Персональные данные (152-ФЗ) у вендора

| Что проверять | Что флагать |
|---|---|
| Поручение на обработку (ст. 6 152-ФЗ) | Есть ли отдельный документ или раздел? Без него — 🔴 если есть ПДн |
| Цели и перечень ПДн | Согласуются ли с нашими целями; «любые данные» — флаг |
| Локализация баз ПДн (ч. 5 ст. 18) | «На территории РФ» — прямое условие; SaaS-вендор с зарубежной инфраструктурой = риск 🔴 |
| ТИПЗ (меры защиты) | Уровень защищённости (УЗ-1..УЗ-4) по приказу ФСТЭК №21; вендор обязан декларировать |
| Субподрядчики (поручения третьим лицам) | Согласие от нас? Реестр? |
| Трансграничная передача | Ст. 12 152-ФЗ — уведомление РКН, страны из приказа №931; если ПДн уходят за рубеж — 🔴 до проверки |
| Утечка | Срок уведомления (РКН + субъекты), кто отвечает, кто платит штраф (ст. 13.11 КоАП — оборотные, до 6 млн для повторного, до 18 млн от 01.05.2025 для первой утечки — `[verify against current КоАП]`) |
| Оборотные штрафы | Кто платит, если виноват вендор? Indemnity |

#### 2.5 Exit и миграция

**SaaS-договор без exit — ловушка долгосрочной зависимости.**

| Что проверять | Что флагать |
|---|---|
| Право выгрузки | Есть ли? Формат (open/CSV/API)? Срок? Отдельно платится? |
| Помощь в миграции | Вендор обязан помочь? Сколько стоит? |
| Срок удержания данных после termination | «Удаляем через 30 дней» — мало для миграции; playbook обычно требует 90+ |
| Продление доступа после exit | Только для выгрузки, без права использования |
| Данные после удаления | Удаление из бэкапов — срок? Сертификат удаления? |
| Расторжение за convenience | Может ли мы выйти за 30/60/90 дней без штрафа? (для multi-year — особенно) |

#### 2.6 Order Form

| Что проверять | Что флагать |
|---|---|
| Приоритет документов | Order Form > MSA > полисы: конфликт решает Order Form — проверить на противоречия |
| Auto-renewal в Order Form | Может расширять MSA («+доп. пользователи», «+продукты») — проверить |
| Приложения referenced | Все приложения, упомянутые по имени, должны быть в наличии, не «по ссылке» |

### Шаг 3: Memo

Как в vendor-agreement-review (Step 5-6), плюс:

**Раздел «SaaS-специфика»** в memo — таблица с автопродлением, ценами,
SLA, ПДн, exit. Каждая строка — проверка со статусом и ссылкой на playbook.

**Renewal handoff:** если договор с автопродлением — после ревизии
автоматически предложить добавить в реестр продлений
(`~/.hermes/legal/commercial-legal/renewal-register.yaml`): контрагент,
название, дата подписания, конец первого срока, дата cancel-by, владелец
бизнес-процесса.
