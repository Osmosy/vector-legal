# /oc-status

Для еженедельного запуска — напоминание вызвать `/oc-status`. Автоматизация
требует scheduler, который не бандлится.

1. Загрузить `_log.yaml`, фильтровать по правилам ниже (или флагам).
2. Загрузить practice profile → стиль директив внешним юристам, подписант,
   бюджетная позиция.
3. Для каждого дела в scope: прочитать matter.md + history.md, черновик письма.
4. Записать markdown в `~/.hermes/legal/litigation-legal/oc-status/[YYYY-MM-DD]/[slug].md`.
5. Если почтовый канал подключен — draft письма; иначе только markdown.
6. `_summary.md` — что отработало, что не отработало и почему.

## Purpose

Каждую неделю писать одно и то же письмо 5–15 внешним юристам — механическая
налоговая нагрузка. Контент per matter стабилен: статус, решения, бюджет/счёт.
Аудитория стабилена: ведущий юрист/партнёр. Тон стабилен: per house style.

## Shared guardrails (канон — practice profile)

**Reviewer note / decision tree / Destination check / Provenance /
No-silent-supplement / Currency trigger / Large input** — см.
practice profile (`~/.hermes/legal/<domain>/CLAUDE.md` → `## Shared
guardrails`, `## Outputs`). Блоки канонизируются там; если текст навыка
расходится с профилем — профиль контролирует.


## Формат выхода

Header — по `## Выходные документы` practice profile (адвокатская тайна
ст. 8 ФЗ-63 — только если готовит адвокат; иначе `КОНФИДЕНЦИАЛЬНО —
ВНУТРЕННИЙ ПРАВОВОЙ АНАЛИЗ`). Один блок **⚠️ Reviewer note** над
deliverable (источники, покрытие, флаги `[review]`, актуальность) и
decision tree «Что дальше?» — по формату из practice profile.
Теги provenance (`[kad.arbitr.ru]` / `[pravo.gov.ru]` / `[sudrf.ru]` /
`[КонсультантПлюс]` / `[user provided]` / `[model knowledge — verify]` /
`[settled — подтверждено YYYY-MM-DD]`) — только по фактическому
происхождению цитаты в этой сессии.

## RF-специфика: модели работы с внешними юристами

В РФ юридическая помощь оформляется двумя путями:

| Модель | Кто | Документ | Оплата |
|---|---|---|---|
| Адвокат | Адвокат (реестр, ст. 8 ФЗ-63) | Соглашение об оказании юридической помощи — ст. 25 ФЗ-63 (существенные условия: предмет, порядок/размер гонорара) | Фикс / почасовые / гонорар успеха (оговорить в соглашении); часто запрос аванса |
| Юрфирма | Юрлицо (не адвокаты) | Договор возмездного оказания услуг (ст. 779 ГК) | Фикс на дело / этап (stage gate) / почасовые с cap |

**Особенности RF-контроля:**

- **Гонорар успеха** допустим и типичен для адвокатов; для юрфирм —
  тоже практикуется, но проверять формулировку (риск квалификации как
  рисковое обязательство); процент от взысканного — от суммы, реально
  полученной
- **Почасовые** — всегда с cap и отчётом в разрезе задач; запрос актов
  (ст. 779–783 ГК) ежемесячно
- **Фикс** — лучше всего контролируется; если меняется объём — доп.
  соглашение, не доплата молча
- **Счета/акты** — проверять против budget и matter.md (за что платим,
  на каком этапе); разрыв = вопрос юристу
- **Госпошлина** — платим сами (не через юриста) и контролируем возвратов
  (ст. 333.40 НК)
- **Судрасходы** — за счёт проигравшей стороны (ст. 101, 110 АПК); в
  статусе отслеживать заявленные оппонентом расходы и наши

## Filtering — какие дела

Дефолт:

- `status != closed`
- `outside_counsel.firm != null` AND `outside_counsel.lead != null`
- Если: last update > 10 дней ИЛИ next_deadline в 21 день

Флаги: `--all` (все дела независимо от свежести), `--slug` (одно дело),
`--no-email` (только markdown).

## Per-matter письмо

```markdown
Тема: [Дело] — статус и бюджет на [дата]

[Ведущий], добрый день.

По делу [name] (дело № ___):

1. **Статус:** [судебная фаза, последнее событие]
2. **Что ждём от вас:** [конкретно — до какой даты]
3. **Бюджет/счёт:** [потрачено / утверждено / ожидается; вопросы по актам]
4. **Ключевые сроки:** [заседание, сроки обжалования — ст. 259/276 АПК]

[Подписант]
```

Правила:

- Нумерованные пункты; дедлайны жирным; бюджет отдельной цифрой
- Не пересказывать дело — читать в matter.md
- Вопросы по счёту формулировать как «вопросы по акту № », не обвинения
- Копия — внутренним владельцам (business, finance)

## `_summary.md`

созданы, какие аномалии по счетам.
