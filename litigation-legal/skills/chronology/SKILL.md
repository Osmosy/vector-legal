# /chronology

1. Загрузить `~/.hermes/legal/litigation-legal/matters/[slug]/matter.md` →
   теория дела, pivot-факт, ключевые факты.
2. Загрузить `~/.hermes/legal/litigation-legal/CLAUDE.md` → источники
   документов, шаблон папки дела.
3. Определить источники в порядке: пути, данные пользователем в этой
   сессии → папка дела по умолчанию → заявленные источники из profile.
4. Для читаемых источников: извлечь датированные события. Для недоступных:
   отметить в Gaps.
5. Дедуп, merge со списком источников на каждое событие.
6. Тегировать значимость (🔴/🟡/⚪) по теории дела.
7. Записать `~/.hermes/legal/litigation-legal/matters/[slug]/chronology.md`
   (или вариант по флагу).
8. Если есть предыдущая версия: номер версии +1, diff-сводка пользователю.
9. Подтвердить: «Вот что собрал. Прогони 🔴 записи — я что-то неверно оценил?»

## Формат выхода

Header — по `## Выходные документы` practice profile (адвокатская тайна
ст. 8 ФЗ-63 — только если готовит адвокат; иначе `КОНФИДЕНЦИАЛЬНО —
ВНУТРЕННИЙ ПРАВОВОЙ АНАЛИЗ`). Один блок **⚠️ Reviewer note** над
deliverable (источники, покрытие, флаги `[review]`, актуальность) и
decision tree «Что дальше?» — по формату из practice profile.
Теги provenance (`[kad.arbitr.ru]` / `[pravo.gov.ru]` / `[sudrf.ru]` /
`[КонсультантПлюс]` / `[user provided]` / `[model knowledge — verify]` /
`[settled — подтверждено YYYY-MM-DD]`) — только по фактическому
происхождению цитаты в этой сессии.

## RF-специфика: доказательственная база

Хронология в РФ-процессе — не просто заметка. Каждое событие с датой и
доказательством попадает в:

- **Исковое заявление** (ст. 125 АПК: обстоятельства + доказательства) —
  хронология становится основой описательной части
- **Отзыв** (ст. 131 АПК) — контр-таймлайн на оппонента
- **Судебные документы**: объяснения, апелляция, кассация

Каждое событие снабжается:

```markdown
### [YYYY-MM-DD] — [короткое название события]
- **Что:** [факт — одно предложение]
- **Доказательство:** [договор №4.2 от 12.03.2024, п. 3; счёт 145 от 01.04.2024;
  переписка email 2024-04-15 14:32; скан акта стр. 2]
- **Режим защиты:** [открытое / КТ (режим введён) / адвокатская тайна]
- **Сигнификант:** 🔴/🟡/⚪ — почему для теории дела
```

**Критично:** каждое 🔴 событие должно иметь доказательство, которое можно
представить в суд. Событие без доказательства — `⚪ (unverified)`; перед
подачей иска проверить, что каждое утверждение иска подтверждается документом
(иначе недоказуемо — ст. 65 АПК burden of proof; ст. 56 ГПК).

## Оговорки disclosed-документов

Перед работой с судебными документами: «Получали ли вы эти документы через
раскрытие/запрос другой стороны?» Если да — использование в других целях
может нарушить соглашение о конфиденциальности или порядок суда. Подтвердить:
«Это использование — в тех же процессах, где документы раскрыты».

## Modes

Скилл работает в двух режимах — выбрать по `## Practice role` в профиле:

- **`--matter` режим (дефолт in-house).** Фокус на истории дела: теория и
  ключевые факты из `matter.md`, источники — из заявленных хранилищ (Nextcloud,
  почта, ЭДО), history.md — внутренний журнал (решения, holds, резервы —
  в хронологию не попадает). Выход matter-центричный.
- **`--documents` режим (дефолт firm).** Фокус на документах: извлечение из
  производственной папки, custodial-файлы. Выход production-центричный.

## Форматы флагов

- `working` — рабочая хронология (дефолт): события + доказательства + gaps
- `sof` — statement of facts: нарратив для процессуального документа,
  каждое предложение с доказательством
- `witness-[имя]` — события, связанные с конкретным человеком (для
  допроса ст. 88 АПК / witness statement)

## Purpose

Факты случаются в порядке. Хронология — хребет каждого нарратива: statement
of facts, memo для резерва, подготовка к допросу, witness prep. Сборка руками —
медленно; AI хорош в структурном извлечении. Ловушка: garbage-in, garbage-out.
Скилл тянет из источников, заявленных в профиле, и из загруженного пользователем.

## The build

### 1. Собрать события

Для каждого документа/источника: даты, действия, суммы, обязательства.
Каждое событие: дата, участники, что произошло, доказательство (источник).

### 2. Дедуп и merge

Одинаковое событие в нескольких источниках → merge с указанием всех
источников. Противоречивые версии — обе с флагом `[review]`.

### 3. Тегирование по теории дела

- 🔴 = pivot-факт, изменение позиции, сильное доказательство
- 🟡 = поддерживающее событие
- ⚪ = контекст, фоновые события

### 4. Gaps

Чего не хватает: документы не читаются, даты пропущены, переписка неполна.
Определить, что дособрать и кто может предоставить.

### 5. Verbatim правило

Дословные цитаты из документов — только с точным фрагментом перед глазами
и ссылайся на место (стр., пункт). Иначе — пересказ без кавычек с
`[verify exact quote — стр. __]`.

## Запись версий

Хронология — живой документ. Версии: `chronology-v1.md`, `chronology-v2.md`.
Diff-сводка при каждой новой версии. Финальную версию — только после
подтверждения.
