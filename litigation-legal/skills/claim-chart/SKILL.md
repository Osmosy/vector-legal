# /claim-chart

1. Загрузить `~/.hermes/legal/litigation-legal/CLAUDE.md` → роль, header,
   decision posture, источники.
2. Если workspaces включены — подтвердить активное дело; загрузить `matter.md`
   (сторона, юрисдикция, фаза, теория, тезисы).
3. Режим: `--civil` (средство защиты: взыскание долга/убытков/неустойки,
   признание сделки недействительной, и т.п.) или `--patent` (в РФ-контексте
   только если конкретное дело об IP — редко; работать в RFC-логике
   патентного спора по ГК ч. 4).
4. Для civil: базовый состав требования (элементы) — уточнить у пользователя
   надлежащую норму (ГК/ЗоЗПП/СГС и т.п.) и подтвердить. Не тянуть состав
   из модельных знаний молча — `[model knowledge — verify]`.
5. Маппить элементы против цели (наши доказательства / позиция оппонента /
   chart под проверкой). Каждый cell — pin-cite.
6. Выпустить gap-list (civil) / needs-evidence list — приоритетный выход.
7. Записать markdown + CSV; header на каждом выходе.
8. Записать в папку дела; добавить строку в history.md.
9. Summary: требование, цель, фаза, счёт элементов, gap-list, пути файлов.

## Формат выхода

Header — по `## Выходные документы` practice profile (адвокатская тайна
ст. 8 ФЗ-63 — только если готовит адвокат; иначе `КОНФИДЕНЦИАЛЬНО —
ВНУТРЕННИЙ ПРАВОВОЙ АНАЛИЗ`). Один блок **⚠️ Reviewer note** над
deliverable (источники, покрытие, флаги `[review]`, актуальность) и
decision tree «Что дальше?» — по формату из practice profile.
Теги provenance (`[kad.arbitr.ru]` / `[pravo.gov.ru]` / `[sudrf.ru]` /
`[КонсультантПлюс]` / `[user provided]` / `[model knowledge — verify]` /
`[settled — подтверждено YYYY-MM-DD]`) — только по фактическому
происхождению цитаты в этой сессии.

## THE CHART IS A DRAFT, NOT A FINDING

**Это правило должно быть сверху каждого выхода. Не убирать, не смягчать.**

## RF-специфика: таблица требований

### Структура таблицы (основание + доказательства + расчёт)

| # | Элемент состава | Правовое основание | Факт по делу | Доказательство | Статус | Расчёт | Прим. |
|---|---|---|---|---|---|---|---|
| 1 | Действие/обязательство | ст./п. [норма] | [факт] | [до-кумент, лист] | ✅ доказано / 🟠 gap / 🔴 конфликт | — | |
| 2 | Нарушение | | | | | | |
| 3 | Убытки/размер | | | | | [расчёт] | |
| 4 | Причинная связь | | | | | | |
| 5 | Срок давности соблюдён | ст. 196 ГК | | | | | |

Для неустойки и процентов — отдельный блок расчёта:

- Неустойка (ст. 330 ГК): база × ставка × дни; проверить на снижение
  по ст. 333 ГК (суд снижает несоразмерную) — и как риск, и как защита
- Проценты (ст. 395 ГК): ключевая ставка ЦБ (проверить актуальную
  [ЦБ РФ — verify] на даты)
- Убытки (ст. 15 ГК): реальный ущерб + упущенная выгода; доказать размер
  и причинную связь

### Истец vs ответчик

Сторона определяет направление каждой ячейки:

- **Наш иск (истец):** каждый элемент состава должен быть доказан ✅,
  слабое → 🟠 gap → стратегия добыть/купировать
- **Наш ответ (ответчик):** достаточно опровергнуть **один** элемент —
  искать weakest link; таблица обороны строит «контр-таблицу» по каждому
  элементу оппонента

### Обязательные проверки RF

1. **Подведомственность** — АС по ст. 27–33 АПК или СОЮ по ст. 22 ГПК?
2. **Досудебный порядок** — обязателен ли для этого требования:
   (а) ч. 5 ст. 4 АПК — денежные требования из договоров/сделок/неоснов.
   обогащения: 30 дней, если иное не в договоре/законе; (б) п. 2 ст. 452 ГК —
   изменение/расторжение договора; (в) претензионный срок в договоре;
   (г) обязателен ли по федеральному закону (например, ч. 4 ст. 124.5 ГК
   для споров с операторами связи). Гап — иск возвращают (п. 2 ч. 1
   ст. 148 АПК).
3. **Срок давности** — по каждому требованию отдельно; прерывание
   (ст. 203 ГК), восстановление только для физлиц (ст. 205 ГК).
4. **Надлежащий ответчик** (ст. 36, 37 АПК) и **соучастие**.
5. **Расчёт взыскиваемого** — приложить к иску (ст. 126 АПК).

## Элементы civil-составов — справочник

Типовые составы по ГК (все — `[модельные знания — verify против
первоисточника]`):

- **Взыскание долга:** договор/сделка → обязательство → срок/нарушение →
  долг + санкции
- **Неосновательное обогащение (гл. 60 ГК):** приобретение за счёт другого →
  без основания → возврат/возмещение
- **Убытки (ст. 15 ГК):** противоправное действие → вина/без вины (предприн.
  ст. 401) → убытки → причинная связь → размер
- **Недействительность сделки (§ 2 гл. 9 ГК):** порок (закон/форма/полномочия/
  кабальность) → последствия двусторонняя реституция (ст. 167)
- **Долг + неустойка + % (ст. 395 ГК):** денежное обязательство → просрочка →
  размер за период
- **Защита деловой репутации (ст. 152 ГК):** распространение + порочащий +
  несоответствие действительности

Если тип требования в этом списке нет — не выдумывать состав; спросить
подтверждающую норму у юриста.

## Формат вывода

1. **Таблица** (markdown) — каждый элемент с ячейками
2. **Расчёт** (отдельная секция, если есть числовые требования) — с
   формулами и датами; проверяемая арифметика
3. **Gap-list** — приоритетный выход:

```markdown
## Gap-list — чего не хватает

### 🔴 Блокирующие (без них состав не доказан)
- [Элемент] — [что нужно]: [куда бежать за документом/фактом]

### 🟠 Риски (есть, но уязвимы)
- [Элемент] — [уязвимость]: [как закрывается]

### Мониторинг
- [Что отслеживаем]
```

4. **Сводка:** требование, сторона, фаза, счёт элементов, файлы.

## Правила записи ячеек

- Каждый cell: pin-cite (ст./п./абзац; документ, номер, дата, страница)
- Апостроф-нейтрализация Excel: значения, начинающиеся с `=`, `+`, `-`, `@`,
  tab, CR — префикс `'`
- `_sources` companion CSV для каждого файла — колонка для provenance
- 🔴 события/доказательства требуют [review] от юриста
