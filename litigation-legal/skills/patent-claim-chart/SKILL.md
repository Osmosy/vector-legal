## A CHART IS A DRAFT, NOT A FINDING OR CONTENTION

Таблица — черновик для поверенного/СИПН-адвоката, не вывод о нарушении,
не заключение о ничтожности. СИПН решает, не таблица.

## Положение РФ-права

- **Состав патента:** независимый + зависимые пункты (ст. 1354 ГК).
  Признаки: существенные признаки, характеризующие изобретение.
  Формула должна быть выражена техническими средствами; «группа
  изобретений» допустима.
- **Объём прав:** определяется формулой; описание служит **для
  толкования** (п. 2 ст. 1354 — « описание и чертежи служат
  исключительно для толкования формулы» — формально: не для расширения).
  Творческий характер — п. 3 ст. 1350 (новизна мировой + промышленная
  применимость + изобретательский уровень).
- **Толкование признаков:** по Пленуму ВС/ВАС и практике СИПН,
  признаки толкуются через описание и чертежи; «средство для...» —
  родовой признак (аналог means-plus-function, но более либерально
  в РФ; конкретное средство раскрывается в описании).
- **Независимость признаков / зависимые пункты:** каждый зависимый
  содержит доп. признаки родительского; рисуются отдельные строки
  «additional limitations» — execute, don't gesture.
- **Экономические эквиваленты** как doctrine: в РФ аналог doctrine of
  equivalents — используется принцип «признак выражен эквивалентом»
  с учётом того, знал ли о нём специалист на дату приоритета;
  СИПН-практика неоднородна `[verify]`. Не переносить test «function-
  way-result» США напрямую.
- **Патентная чистота/исключения:** ст. 1359 ГК (не признаются
  нарушением: применение в личных целях, при чрезвычайных
  обстоятельствах, в эксперименте, при «прежнем использовании» —
  prior use right ст. 1361 ГК).

## Интейк (доп. для патентного режима)

- Номер патента, asserted (независимые) пункты. Зависимые — только если
  заявлены. Don't chart unasserted.
- Дата приоритета (для новизны/уровня техники).
- Существующие толкования: СИПН-решения, позиции сторон, поясняющие
  документы спорящих сторон.

## Workflow (патентный режим)

### Шаг 1: Парсинг формулы

Разобрать независимый пункт на пронумерованные признаки `[1a]`, `[1b]`,
`[1c]`. Правила парсинга:

- **Преамбула** — note, ограничивающая ли (вопрос толкования).
- **Переходная фраза:** «содержащая/включающая» (open, RU-аналог comprising)
  / «состоящая из» (closed) / «состоящая преимущественно из» (semi-open).
  RU-практика: «содержащая» — открытая; «состоит из» — закрытая.
- **Средство плюс функция** («средство для...», блок/узел/модуль): RU
  подход мягче §112(f) — конкретное средство описано в описании; если
  описание не раскрывает структуру — флаг `construction-dependent`.
- **Признаки, разделённые запятыми/точками с запятой; нумерация
  стабильна** — это скелет таблицы.
- **Markush-группы, Jepson-признаки** («известный... отличающийся
  тем»), продукт-процесс, зависимости порядка шагов — флаг с комментом
  нестандартного толкования.
- **Зависимые пункты** — ссылаются на родителя; в таблица включать только
  дополнительные признаки. **Execute, don't gesture:** если спаренные
  зависимые в деле — реальные строки дополнительных ограничений, не
  замета «зависимые должны быть разучены».
- **Структурные существительные с широко толкуемыми когнатами:**
          по умолчанию `construction-dependent` — термины, чаще всего
          спорные в СИПН; узкое прочтение (заострённый шип vs любой
          выступ) или широкое (канал vs любой проход). Пометить и в
          `_constructions`.

Показать парсинг пользователю, дождаться подтверждения. Ложный парсинг
отравляет каждую строку ниже.

### Шаг 2: Проверка толкований

Флагнуть спорные термины:

- Триальные термины или термины с определением из описания
- Термины с патентной историей (амендменты, отказы-дизавоу —
  `Пленум ВАС/ВС` и СИПН-практика)
- Функциональный язык («настроен, чтобы», «приспособлен», «работает,
  чтобы»)
- Относительные термины («существенно», «примерно») — неопределённость
- Компьютерно-реализуемые признаки — патентоспособность ст. 1350 п. 5
  (алгоритмы «как таковые») — риск СИПН по ничтожности

Для каждого флага — при каких толкованиях матч работает, при каких
падает. Если есть СИПН-определяющие указания, применить. Если споры
идут — таблица под каждую сторону.

### Шаг 3: Мэппинг

Для каждого признака — для каждого целевого объекта (продукт/прототип/
прайор-арт):

1. **Найти доказательства.** Продукт: doc-и, мануалы, дашборды, исходники,
   teardown, показания, экспертные мнения. Прайор-арт: колонка/строка —
   для патентов, абзац для заявок, страницу для НПА-приложений.
2. **Верbatim-цитата,** символ-в-символ. Без парафраза. Обрезка sentence-
   boundaries и пометка elision.
3. **Характеристика мэппинга.**

   | Тип | Значение |
   |---|---|
   | `literal` | Признак буквально в целевом объекте / прайор-арте |
   | `construction-dependent` | Буквально под толкованием X, падает под Y |
   | `doe` (эквивалент) | Эквивалент признака (function-way-result в РФ — ограниченно, учитывая дату приоритета) |
   | `anticipation` | Все признаки в одном источнике (ст. 1351 п. 1 — новизна) |
   | `объединение` | Вторичный источник подсказывает недостающий признак; мотивация объединения — спорно, нужно показать (`[verify]`) |
   | `partial` | Часть признака присутствует |
   | `not-found` | Признак отсутствует |
   | `needs-evidence` | Не определить из доступных материалов |
   | `indirect` | Косвенное нарушение — ст. 1352 п. 3 (склонение, поставка средства) |

4. **Per-cell состояние.** `mapped` / `mapped-doe` / `partial` /
   `not-found` / `needs-evidence` / `construction-dependent` /
   `anticipation` / `obviousness-combination`.
5. **Флаг открытых вопросов:** «эта строчка матчится, если [X]. Нужен
   teardown / исходный код / показания / эксперт.»

**No silent supplement.** Тонкая документация = `needs-evidence`, не
экстраполирование из похожих продуктов. Приор-арт статус не очевиден →
`prior-art-status: needs-evidence` (ст. 1351 новизна, п. 2 — уровень
техники; дата приоритета и regime АИА/до-АIA-аналог: ФЗ-1266 от 12.03.2014
ст. 1362 (переходные положения) — `[verify против current редакций]`)

### Шаг 4: Зависимые пункты — execute

Если в asserted claim входят зависимые — для каждого добавить строки
«дополнительных признаков» (только additional limitations поверх
родителя) — не gesture.

### Шаг 4.5: DOE supplements — execute, don't gesture

Для literal-попавших признаков: если есть сомнения в эквиваленте —
пометить `needs-analysis` не выводить «суд решит» (это gesture). Перечень
открытых вопросов в конце таблицы.

### Шаг 5: Indirect, divided, willfulness (только infringement)

- **Co-conspiracy / aiding** (ст. 1252): если нет одного leaf-признака
  но поставка «для нарушения» — в СИПН спорно; флаг.
- **Divided (разделённое) осуществление** — совокупность действий двух
  или нескольких лиц для полного охвата признаков. В РФ doctrine не сформулирована
  как в США — СИПН-практика не однородная, `[verify]`.
- **Willfulness (умышленность)** — не влияет на размер компенсации по
  п. 3 ст. 1252 (формула фиксированная), но влияет на убытки/встречные.

### Шаг 6: Invalidity thresholds (только invalidity)

Для ничтожности: все признаки в одном документе (anticipation / новизна
ст. 1351 п. 1), или объединение документов с мотивацией (изобретательский
уровень п. 2 — СИПН-практика «мотивация модификации» неоднородна).
Thresholds помечать `[verify]`.

### Шаг 7 (review sub-mode): Audit

Таблица + проверки пропущенных признаков, некорректных мэппингов, полей
без provenance — для независимой ревизии поверённым.

## Патентные guardrails (доп. к общим)

- Парс без подтверждения — не строить мэппинг (пользователь подтверждает
  признаки до таблицы)
- Эквиваленты — не механическое «same result»: СИПН смотрит специфику
- Для СИПН-специфики — только черновик; поверенный финализирует
- Ст. 1359 (не наруш.) — проверять до флага

## Что этот навык не делает

Не даёт заключения о нарушении/ничтожности; не подменяет патентного
поверенного; не определяет размер компенсации (эксперт/суд/СИПН);
не ведёт дело в суде.
