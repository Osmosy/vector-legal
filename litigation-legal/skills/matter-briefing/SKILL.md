# /matter-briefing

1. Загрузить `~/.hermes/legal/litigation-legal/CLAUDE.md` → риск-калибровка,
   стейкхолдеры.
2. Прочитать `matter.md` + `history.md` + строку `_log.yaml`.
3. Произвести брифинг: позиция, изменения с последнего update, ближайший
   срок, открытые вопросы, чек риск-переоценки («поле `risk:` ещё
   соответствует реальности?»).
4. Флагнуть staleness: `last_updated` > 30 дней → пометить.

## Purpose

Чистая картина по одному делу за время пути до переговорки. Позиция,
изменения, что дальше, что стоит переоценить.


---

## Shared guardrails (канон — practice profile)

**Reviewer note / decision tree / Destination check / Provenance /
No-silent-supplement / Currency trigger / Large input** — см.
practice profile (`~/.hermes/legal/<domain>/CLAUDE.md` → `## Shared
guardrails`, `## Outputs`). Блоки канонизируются там; если текст навыка
расходится с профилем — профиль контролирует.


## Load context

- `~/.hermes/legal/litigation-legal/matters/_log.yaml` — строка
- `~/.hermes/legal/litigation-legal/matters/[slug]/matter.md` — intake
- `~/.hermes/legal/litigation-legal/matters/[slug]/history.md` — журнал
- `~/.hermes/legal/litigation-legal/CLAUDE.md` — калибровка

**Конфликт-гейт — небходимое.** Прежде чем брифиить, проверить slug в
`_log.yaml`. Нет — отказ: «Дело не intaken, конфликтный чек не пройдён».

## Input

Slug обязателен. Неоднозначно/не передан — спросить из списка активных.

## The briefing

```markdown
[WORK-PRODUCT HEADER — по `## Выходные документы` профиля]

# [Название дела] — брифинг на [сегодня]

**Статус:** [статус/фаза]
**Риск:** [рейтинг] ([severity] × [likelihood])
**Подведомственность:** [АС ... / СОЮ ... / третейский]
**Внешний юрист:** [фирма — ведущий] или наш in-house
**Last updated:** [date] [⚠️ STALE если >30d]
**Конфликт:** [статус — ⚠️ если `pending` или `not-run`]
**СИД:** [статус срока давности]

---

## Одно-абзацевое summary

[Текущая позиция. Что делаем и почему. Pivot-факт, если captured.]

## Что изменилось недавно

[Последние 3–5 записей history.md, новейшие первыми. Если history тонкий — так и сказать.]

## Ближайший срок

**[Deadline]** через [N дней]. [Что дедлайну предшествует: заседание,
обмен документами, досудебный порядок, срок обжалования.]

## Открытые вопросы

[Вопросы, ждущие решения/фактов. Каждый с тем, кто может закрыть.]

## Чек риск-переоценки

**Поле `risk:` = [текущий]. Соответствие реальности?** [Если изменилось —
указать и предложить matter-update.]

## Оценка позиции

[Честная оценка: сильные стороны, слабые стороны, что решит исход.]
[Если есть сомнение в выводе — так и пометить `[model knowledge — verify]`.]
```

## Проверка внешних источников

Проверить актуальный статус дела на kad.arbitr.ru (АС) или sudrf.ru (СОЮ):
свежие определения, заседания, акты `[kad.arbitr.ru]` / `[sudrf.ru]` —
только если реально проверено в сессии; иначе `[model knowledge — verify]`.
