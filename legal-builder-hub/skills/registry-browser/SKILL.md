# /registry-browser

1. Загрузить `~/.hermes/legal/legal-builder-hub/CLAUDE.md` → watched-реестры
   (или прочитать их из `allowlist.yaml`, если профиль ещё не создан).
2. Прогнать workflow ниже.
3. Искать в каждом реестре. Показать совпадения с описаниями.
4. Предложить показать полный SKILL.md для любого совпадения.

---

## Purpose

Найти навыки по всем watched-реестрам. Поиск, превью, решение.

## Загрузка контекста

`~/.hermes/legal/legal-builder-hub/CLAUDE.md` → список watched-реестров.

## Workflow

### Шаг 1: Фетч индексов реестров

Для каждого watched-реестра:

- **GitHub-репозитории:** фетчить листинг каталога `skills/` (через
  web_extract на `https://github.com/<owner>/<repo>/tree/main/skills` или
  GitHub API `https://api.github.com/repos/<owner>/<repo>/contents/skills`),
  затем frontmatter каждого SKILL.md (имя + description). Для навыков в
  подкаталогах — рекурсивно один уровень.
- **Marketplace-реестры** (с `marketplace.json` / индексным файлом):
  фетчить индекс.

Кэшировать индекс локально (`~/.hermes/legal/legal-builder-hub/registry-cache.json`),
чтобы обзор был быстрым. Обновлять кэш, если ему >7 дней или по запросу.
В кэше хранить: имя навыка, реестр, description, путь, дату фетча, commit SHA
(если доступен) — SHA пригодится skill-installer для пиннинга.

### Шаг 2: Поиск

Матчить запрос против имён и описаний навыков. Простой keyword-матч
достаточен — реестры маленькие, fuzzy-поиск избыточен. Учитывать и
русскоязычные запросы, и английские имена навыков (RU-запрос «ревизия
договора» должен находить `nda-review`, `contract-review`, `review`).

Также: обзор по категориям, если реестр так организует навыки.

### Шаг 3: Показать совпадения

```markdown
## Поиск: «[запрос]»

**Найдено [N] навыков в [M] реестрах:**

### [имя-навыка]
**Из:** [имя реестра]
**Описание:** [из frontmatter]
**Язык оригинала:** [RU / EN — из тела SKILL.md]
[Показать полный SKILL.md] [Установить]

### [имя-навыка]
[...]
```

Для каждого результата — одной строкой пометить, адаптирован ли он под право
РФ или это US/иностранный контент: поле **юрисдикция** из frontmatter
(если декларирован) или эвристика по телу (упоминания FRCP / state law → US;
ГК / 152-ФЗ / АПК → RU). US-навыки не скрываются, но получают пометку
«US-контент — перед использованием нужна адаптация под право РФ».

### Шаг 4: Превью

По «показать полный SKILL.md»: фетчить и показывать весь файл целиком.
Пользователь читает до решения об установке. Без сюрпризов. Установка —
только через `skill-installer` (с full trust-пайплайном); «Установить»
здесь — маршрутизация туда, не самостоятельная установка.

### Шаг 5: Добавить реестр

Если у пользователя URL реестра, которого нет в watchlist:

1. Фетчить, валидировать, что это skills-репозиторий (есть `skills/`,
   `*.md` с frontmatter `name:`/`description:` или индекс `marketplace.json`)
2. Показать, что в нём (сколько навыков, какие темы, чей издатель)
3. Проверить лицензию репо (README/LICENSE — через инсталлер-логику SPDX) и
   пометить
4. Вносить в `~/.hermes/legal/legal-builder-hub/CLAUDE.md` → watched-реестры
   И в `allowlist.yaml` → `registries:` — по подтверждению
   пользователя. Не добавлять реестр только в профиль — инсталлер читает
   allowlist, и реестр вне его молча не работал бы в restrictive-режиме.

При добавлении реестра напомнить: «Добавление реестра — trust-решение.
Навыки из него будут проходить allowlist-гейт по издателю — добавьте
GitHub-владельца в `publishers:` тоже, иначе restrictive-режим откажет в
установке даже из добавленного реестра».

## Реестры по умолчанию

- **Vector Legal** (`github.com/<org>/vector-legal`) — наш реестр:
  RU-адаптированные навыки 9 доменов права + инфраструктура. First-party:
  тот же trust-пайплайн, но источник известен.
- **lpm-skills** (`github.com/legalopsconsulting/lpm-skills`) — 14 навыков
  legal project management. Practice-agnostic. Хорошая стартовая точка.
  Language: EN, юрисдикция-нейтральный в основном.
- **Lawvable / awesome-legal-skills** (`github.com/lawvable/awesome-legal-skills`)
  и **Lawvable / agent-skills** (`github.com/lawvable/agent-skills`) —
  курируемые US-реестры. Полезны как референс для собственных адаптаций;
  содержание — US-право.
- Пространство для других — экосистема растёт.

## Чего этот навык НЕ делает

- Не устанавливает ничего. Он обзорит. skill-installer устанавливает.
- Не оценивает и не ревьюит навыки. Показывает SKILL.md; судите сами.
- Не ищет по всему интернету. Только watched-реестры.
- Не добавляет реестры без явного подтверждения пользователя.
