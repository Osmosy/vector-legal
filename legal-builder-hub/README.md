# Legal Builder Hub — app store юридических навыков (Vector Legal)

Адаптация [claude-for-legal/legal-builder-hub](https://github.com/anthropics/claude-for-legal)
(Anthropic, Apache-2.0) под Hermes Agent и экосистему Vector Legal.

## Что это

Это «app store» для юридических навыков. Кто пользуется остальными плагинами
Vector Legal — тому сюда: находить, оценивать, устанавливать, обновлять и
убирать community-навыки. В Hermes нет собственного маркета навыков — хаб
закрывает этот пробел с security-постурой, которой маркету не хватает.

**Каждый community-навык показывается целиком в raw-виде до установки,
сканируется на prompt-injection и оценивается по Legal Skill Design
Framework. Хаб помогает находить и оценивать; решать, чему доверять, — вам.**

## Устанавливаемые навыки запускаются с вашим доступом

Community-навык после установки работает с вашим доступом к клиентским
данным, материалам дел и playbook'ам команды. Хаб трактует каждую установку
и каждое обновление как trust-решение. Четыре слоя защиты, ни один не
достаточен сам:

- **Allowlist (admin-управляемый):**
  `~/.hermes/legal/legal-builder-hub/allowlist.yaml` декларирует, какие
  реестры, издатели, MCP-коннекторы и лицензии community-навыки могут
  использовать. Режим `permissive` (для Solo) предупреждает о вне-списочном
  или отказывает ему; `restrictive` (для фирм/enterprise; дефолт шаблона)
  отказывает до добавления в список. Allowlist проверяется до того, как
  инсталлер прочитает хоть байт стороннего контента.
- **Raw-источник, не пересказ:** инсталлер показывает полный raw `SKILL.md` —
  не AI-пересказ — до того, как что-то будет записано. Пересказ — удобство;
  навук, делающий что-то непорядочное, обязан делать это в тексте, который
  raw-показ покажет.
- **Эвристические сканы:** и инсталлер, и `skills-qa` сканируют навык на
  паттерны prompt-injection (override/authority-заявления, вне-scope чтения
  и записи, внешние URL, скрытый unicode, shell-исполнение, запросы
  креденшелов). Это AI-эвристики — помечены как таковые; чистый скан — не
  аудит безопасности, это приглашение прочитать текст самому.
- **Человеческое подтверждение, каждый раз:** ничто не пишется на диск без
  свежего напечатанного «да». Подтверждение не выводится из более ранних
  сообщений. Для defense-in-depth инсталлер рекомендует гонять фетч/анализ
  в read-only контексте, чтобы Write-возможности появлялись только после
  подтверждения.

Обновления — та же постура: `auto-updater` пинится к commit SHA (не к
мутируемым тегам), показывает полный diff, повторно сканирует новую версию
(гейт GlassWorm: доверенный издатель может прислать payload в minor bump)
и требует явного подтверждения на каждое обновление. Режима авто-применения
нет.

Если установленный навык пошёл вразнос: `disable [навык]` затихаривает его
без удаления файлов; `uninstall [навык]` убирает (архивируя, не стирая).
Оба ограничены community-навыками, установленными через хаб, и отказываются
трогать навыки доменных плагинов Vector Legal.

## Три уровня доверия при установке

| Уровень | Что происходит | Кто гейтит |
|---|---|---|
| **1. Лицензия** | SPDX-паттерн-матч заявленной лицензии против `licenses:` в allowlist | Структурный гейт (файл allowlist) |
| **2. Source scan** | Raw SKILL.md + структурная trust-проверка + skills-qa + эвристика инъекций | AI-сигналы поверх видимого пользователю текста |
| **3. Подтверждение** | Явное «да», напечатанное после всего | Только человек |

## Legal Skill Design Framework

Ядро QA (`skills-qa`): **13 параметров** проектирования — аудитория, форма
работы, порог делегирования, входные требования, версионирование/владелец,
полосы уверенности, failure modes, границы scope, логика эскалации, Trust
Surface, свежесть, структура, конфликты — плюс **3 юридических failure
mode** (консультация vs. поддержка; защита/адвокатская тайна; разрыв
ответственности) и **4-уровневый вердикт**: Ready / Some Concern / Material
Concerns / REFUSE. REFUSE не advisory: подтверждённая эксфильтрация или
кража креденшелов останавливает установку без install-промпта и override-
флага.

## Структура

```
legal-builder-hub/
├── CLAUDE.md                      # Шаблон профиля хаба (заполняет cold-start)
├── README.md                      # Этот файл
└── skills/
    ├── cold-start-interview/      # Тип практики → стартер-пак → установка
    ├── registry-browser/          # Обзор GitHub-реестров навыков
    ├── skill-installer/           # Лицензия → raw-показ → trust-проверка → QA → «да»
    ├── skills-qa/                 # Legal Skill Design Framework + скан инъекций
    ├── auto-updater/              # Обновления: SHA-pinning, diff, ресурскан, confirm-гейт
    ├── related-skills-surfacer/   # Предложения смежных после задач
    ├── skill-manager/             # Референс: uninstall/disable/re-enable workflows
    ├── disable/                   # Отключить без удаления файлов
    ├── uninstall/                 # Убрать (архивировать) + снять регистрацию
    └── customize/                 # Точечная правка профиля хаба
```

## Быстрый старт

```
cold-start-interview          # 5 вопросов → стартер-пак под тип практики
registry-browser ревизия      # что есть по теме
skill-installer <навык>       # установка с полным trust-пайплайном
```

До cold-start хаб работает в permissive-режиме с пустым allowlist и
предупреждает об этом при каждой установке.

## Установка в Hermes (отличие от плагинов CFL)

Доменные плагины Vector Legal ставятся как файлы в `~/.hermes/skills/` с
регистрацией через `skill_manage` (Hermes-конвенция: frontmatter
`name`/`description`/`argument-hint`, RU-тело). Хаб ставит community-навыки
туда же:

- **Путь установки:** `~/.hermes/skills/[имя-навыка]/` — не
  `~/.claude/plugins/...` (пути CFL).
- **Инкорпорация:** через `skill_manage` (`create`, при необходимости
  `category`), с записью действия в `install-log.yaml` — чтобы
  disable/uninstall умели снимать регистрацию.
- **Конвенция:** Hermes SKILL.md-стандарт. Навык в CFL/Anthropic-формате
  (`user-invocable`, Pitfalls-секции, EN-тело) при инкорпорации
  нормализуется: пересборка frontmatter, RU-тело, Pitfalls-содержимое
  переносится в guardrails.

## Practice profile

Конфигурация живёт в `~/.hermes/legal/legal-builder-hub/CLAUDE.md`
(шаблон — `PRACTICE-PROFILE.md` в корне плагина; имя шаблона отличено от
`CLAUDE.md`, чтобы репо-шаблон не маскировался под инструкцию агенту).
Профиль содержит реестры-источники,
режим allowlist, deployment context, пороги свежести, роль (юрист/не-юрист)
и таблицу установленного. Профиль улучшается по мере использования: хаб
перечитывает его при каждом `registry-browser` и `related-skills-surfacer`.

## Отличия от CFL

1. **Пути:** `~/.hermes/skills/` + `~/.hermes/legal/legal-builder-hub/`
   вместо `~/.claude/plugins/config/claude-for-legal/legal-builder-hub/`;
   инкорпорация через `skill_manage`.
2. **Конвенция навыков:** Hermes SKILL.md-стандарт (RU-тело,
   frontmatter name/description/argument-hint, без Pitfalls) вместо
   CFL/Anthropic формата.
3. **Уровни доверия:** CFL держит allowlist+raw-показ+аппрув в одном
   пайплайне; здесь они переформулированы как три явных уровня (лицензия →
   source scan → подтверждение) — то же содержание, явнее для пользователя.
4. **Архивирование вместо удаления:** disable/uninstall в CFL переименовывают
   или стирают; здесь uninstall по умолчанию архивирует навык в
   `archive/[навык]-[дата]/` с `RESTORE.md` — необратимое удаление только по
   явному вторичному подтверждению.
5. **Реестры:** дефолтный allowlist — наш vector-legal (first-party) и
   lpm-skills; lawvable-реестры (US) — как референс. RU-пометка юрисдикции
   в выдаче registry-browser.
6. **Уведомления:** Slack → Telegram через Hermes gateway (без настроенного
   gateway — дайджест в файл).
7. **Гейты свежести:** поля freshness сохранены, но верификация источников
   ориентирована на `pravo.gov.ru` / `kad.arbitr.ru` (КонсультантПлюс/Гарант
   без MCP — только декларация автора + ручная проверка).
8. **Hooks-поверхность:** CFL-хабы проверяют `hooks/hooks.json` и
   `.mcp.json`; в Hermes эквиваленты поверхностей — исполняемые скрипты,
   toolset-разрешения, cron/delegation — скан параметра Trust Surface
   переориентирован на них.
9. **Роль-роутинг:** сохранён (не-юрист не получает install-промпт на
   Material Concerns/REFUSE), примеры адаптированы: адвокатский реестр
   региона, ФЗ-324 бесплатная юрпомощь, юрклиники.
