# /launch-review

## Инструкции

1. **Загрузить `~/.hermes/legal/product-legal/CLAUDE.md`** → фреймворк
   (`## Review framework`) + калибровка (`## Risk calibration`) + процесс
   (`## Launch review process`) + эскалации. Плейсхолдеры → остановиться и
   предложить `cold-start-interview`; либо пользователь говорит
   **«provisional»** — работать с generic дефолтами РФ, метки `[PROVISIONAL]`.

2. **Получить PRD + сопутствующие документы:** из файла, ссылки или задачи
   трекера (если трекер подключён — подтащить историю комментариев).

3. **Понять, что запускается** — до чеклиста, простым языком:
   - Что это делает? Кто пользователи — существующие, новые, новый сегмент?
     Есть ли несовершеннолетние?
   - Что нового против уже проверенного?
   - Новые данные, вендоры, заявления, юрисдикции, рынки (RU/экспорт)?

4. **Детекция ИИ — до прохода по фреймворку.** Ищем ИИ в любой форме: модель,
   скоринг/классификация, генеративный контент, рекомендации, предсказания.
   Маркеры даже без слова «ИИ»: «умный», «автоматически», «персонализация»,
   «сгенерировано». При детекции — флагнуть и параллельно запустить
   `/ai-governance-legal:use-case-triage` (если плагин установлен); категория 9
   закрывает детали.

5. **Пройти фреймворк** — 9 категорий из профиля (дефолт ниже). Пропуск
   категории — честно, одной строкой с причиной.

6. **Откалибровать каждую находку** по `## Risk calibration` (см. ниже).

7. **Собрать memo** в house-формате, эскалации по матрице, при подключённом
   трекере — summary в задачу.

```
cold-start-interview        # если калибровки ещё нет
/launch-review PROJ-1234
```

## Purpose

Прочитать PRD, проверить каждую категорию фреймворка этой команды,
откалибровать против того, что реально блокирует здесь, и выдать ревью в
house-формате. Цель: PM читает и точно знает, что должно произойти до шипа.

Калибровка — то, что отличает этот навык от generic чеклиста. Если таблица
говорит «новый сбор ПДн → политика обновлена, шипится за 1–2 дня» — не писать
«может потребоваться полноценная оценка воздействия и консультация РКН».
Калибровке команды верить, а не учебнику.

## Framework: 9 категорий (дефолт РФ)

Полная версия с чек-листами: `references/nine-category-framework-ru.md`.
Категории — стабильный каркас; регуляторные режимы внутри каждой
исследуются под сектор/аудиторию/рынки перед калибровкой severity.

| # | Категория | Ключевой вопрос | Auto-skip если |
|---|---|---|---|
| 1 | Договорные обязательства и оферта | Противоречит ли опубликованным ToS/оферте/SLA/маркетингу? | Нет пользовательских изменений |
| 2 | Персональные данные (152-ФЗ) | Новый сбор ПДн, новая цель, новый получатель, трансграничка? | Нет изменений в данных |
| 3 | Информационная безопасность | Новая поверхность атаки, новые данные в покое, новые доступы? | UI-only без бэкенда («UI-only» с новым API-вызовом — не UI-only) |
| 4 | IP и контент | Чужой код/контент/шрифты? Copyleft? Генерация? UGC без процедуры жалоб? | Нет новых зависимостей и контента |
| 5 | Третьи лица | Новый вендор/партнёр/интеграция? Поручение на обработку ПДн? | Нет новых внешних сторон |
| 6 | Регуляторика, реестры, сертификация | Регулируемый сектор? Реестры? ТР ТС? «Честный ЗНАК»? Лицензии? | Те же пользователи, сектора, рынки |
| 7 | Маркетинг и реклама (ФЗ-38) | Заявления, требующие доказательств? Обязательные предупреждения? ЕРИР-маркировка? | Нет маркетинговой составляющей |
| 8 | Платежи и фин-отношения (ФЗ-161/115/54) | Как платят? Приём платежей? ККТ? ПОД/ФТ? | Изменений в монетизации нет |
| 9 | ИИ и алгоритмы (ЭПР / ГОСТ Р 59276 / РС) | ИИ-компонент? Объект ЭПР? Рекомендательная система (маркировка + отключение, ст. 10.2-10.3 ФЗ-123)? Автоматические решения без человека? | ИИ не детектирован в шаге 4 |

**Для каждой категории выводить:**

```markdown
### [N]. [Категория]

**Проверено:** [что смотрел]
**Находка:** [Чисто | Требует работы | Блокер | Пропущено — причина]
**Детали:** [в чём issue — конкретно по этому PRD, не generic]
**Калибровка:** [из профиля: обычно FYI / обычно требует X / обычно блокирует]
**Действие:** [что должно произойти, кто владелец, к какому сроку]
```

## Сектор-оверлеи (РФ)

Базовый фреймворк — универсальный. Если запуск затрагивает сектор ниже,
добавить оверлей по затронутым категориям. Режим сектора часто поставляет
контролирующий минимум, а не сноску — не давать ему утонуть в категории 6.

| Сектор | Оверлей-режимы (РФ) |
|---|---|
| **Дети / несовершеннолетние** | ПДн ребёнка до 14 лет — согласие родителя (ч. 4 ст. 9 152-ФЗ); возрастная маркировка (ФЗ-436); ограничения рекламы детям (ст. 6 ФЗ-38); платформенные возрастные рейтинги `[platform policy — verify]` |
| **Игры / лутбоксы / внутреигровая валюта** | Раскрытие шансов; лотерейная грань (ФЗ-138) при призовой механике за деньги; сторовые правила для IAP `[platform policy — verify]`; реклама игры — ФЗ-38 |
| **Финтех / платежи** | ФЗ-161 (платёжная система, НСПК, безопасность), ФЗ-115 (ПОД/ФТ, идентификация), ФЗ-54 (ККТ), лицензии ЦБ при переводе средств; реклама финуслуг — ст. 28 ФЗ-38 (обязательные предупреждения) |
| **Медицина / здоровье** | Лицензирование меддеятельности (ПП № 852); реклама медуслуг/лекарств/БАД — ст. 24 ФЗ-38 (предупреждения, «имеются противопоказания»); СЭД/регистрация медизделий (ЕАЭС); мед-ПДн — спецкатегории (ст. 10 152-ФЗ) + приказ МЗ № 950н |
| **Образование / EdTech** | Лицензия при выдаче документов об образовании (ФЗ-273); реклама — правдивость результатов (баллы ЕГЭ и пр.); ПДн несовершеннолетних |
| **HR / найм** | ТК РФ (ст. 64 — отказы), 152-ФЗ на кандидатов; биометрия (ФЗ-572-2021) при видеоинтервью; ИИ-скрининг — категория 9 + ЭПР-пороги `[model knowledge — verify]` |
| **Телематика / связь** | Лицензия связи (ст. 29 ФЗ-126), СКЗИ/ФСБ-уведомления, хранение трафика/метаданных (ст. 64 ФЗ-126, ст. 10.6 ФЗ-149), реестр телематических услуг; «Яровая»-пакет |
| **Госданные / госсектор** | ГОСТ-сертификация СЗИ, контур КИИ (ФЗ-187), импортозамещение ПО (реестр Минцифры), гостайна — сразу эскалация |
| **Маркетплейс / товары** | ТР ТС сертификация/декларирование; «Честный ЗНАК» по товарной группе; ЗоЗПП: ст. 10 (информация), 26.2 (дистанционно, отказ 7/90 дней), маркировка продавца; правила размещения на агрегаторах (ст. 12.1 ЗоЗПП) |

Сектор не в списке — исследовать режим под конкретный продукт (web search +
`[verify]`) и зафиксировать находку, как novel (шаг «Калибровка»).

## No silent supplement

Если поиск по правовой базе (КонсультантПлюс/Гарант/pravo.gov.ru) вернул мало
или ничего по режиму/практике ФАС — сообщить, что найдено, и остановиться.
Не заполнять пробел из модельных знаний молча: «По [режим] поиск вернул N
результатов. Варианты: (1) расширить запрос, (2) web search с тегом
`[web search — verify]`, (3) пометить как непроверенное и остановиться. Что
выбираешь?» Юрист решает, принимать ли источники пониженной уверенности.

**Тегирование цитат** — см. practice profile → теги источников. По умолчанию
`[model knowledge — verify]`; `[settled — подтверждено YYYY-MM-DD]` — только
после реальной проверки против первоисточника в этой сессии.

## Калибровка severity

Для каждой находки свериться с `## Risk calibration` профиля:

- Совпало с «обычно FYI» → отметить, не блокировать
- Совпало с «обычно требует работы» → назвать работу и тайм-лайн из таблицы
- Совпало с «обычно блокирует» → флагнуть жирно, эскалация по матрице
- **Novel (нет в таблице)** → сказать явно: «Не совпадает ни с одним паттерном
  калибровки — нужен человеческий вердикт», добавить в Launch archive

Субъективные вердикты (`[review]`-флаг на строку) — принцип recoverable error:
недофлагнуть — односторонняя дверь, перeфлагнуть — двухсторонняя, юрист
закроет за 30 секунд.

## Выход

```markdown
[HEADER — по профилю ## Выходные документы]

⚠️ Reviewer note: [один блок — формат из профиля]

# Launch Review: [Имя фичи]

**Дата:** [дата] | **Дедлайн запуска:** [дата] | **PRD:** [ссылка/файл]

---

### Executive Summary

[Блокирует: N. Требует работы: N. Чисто: N. Одна строка — вердикт по калибровке.]

[Категории 1–9 в формате выше]

---

## Что дальше? Выбери, и я помогу:
1. **[Действие по находкам — напр. «обновить оферту + политику»]** — черновик
2. **Эскалировать** — [аппрувер из профиля] короткой эскалацией
3. **Дособрать факты** — вопросы к PM/маркетингу
4. **Наблюдать** — в трекер с датой возврата
5. **Другое**

**Маркетинг-составляющая существенная?** → `/marketing-claims-review`
**Изолированный находка требует глубины?** → `/feature-risk-assessment`
```

## Handoffs

- **marketing-claims-review** — при существенной маркетинговой составляющей
- **feature-risk-assessment** — когда находке нужна глубина больше строки
- **privacy-policy-ru / terms-of-service-ru** — когда ревью выявляет
  необходимость обновить эти документы (новые ПДн, новая монетизация)
- **ai-governance-legal** — при детекции ИИ (use-case triage + AIA)
