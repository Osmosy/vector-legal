# /log-leave — регистрация отпуска/больничного

Добавить запись в `~/.hermes/legal/employment-legal/leave-register.yaml` —
этот файл следит за сроками с первого дня.

## Инструкции

1. **Проверить реестр:** прочитать
   `~/.hermes/legal/employment-legal/leave-register.yaml`. Если нет —
   создать с структурой ниже. Если HRIS подключён (профиль → `## Системы`)
   — данные из HRIS, YAML — зеркало для юридических сроков.

2. **Собрать минимум:**
   - Работник: **псевдоним или ID** (не ФИО в открытом реестре — ПДн).
     Соответствие ID ↔ ФИО — вне реестра, у HR.
   - Должность/подразделение
   - **Тип отпуска** (см. таксономию ниже)
   - Даты: начало / планируемый конец / основание (заявление, приказ №, дата)
   - Что уже сделано (приказ, уведомление, справка)

3. **Проверить сроки до записи** (см. «Обязательные действия по типам») —
   если действие уже просрочено, пометить 🔴 сразу при записи.

4. **Дописать в реестр** (одна запись = один период; продление больничного —
   новая запись со ссылкой на исходную).

5. **Подтвердить записью в выводе:** что записано, какие сроки теперь
   отслеживаются, ближайший дедлайн.

## Таксономия отпусков (для полей type)

| Тип | Норма | Ключевые строки |
|---|---|---|
| `annual` — основной оплачиваемый | ст. 115 (28 дней), 122–123 (график) | уведомление о начале — под подпись за 2 недели |
| `additional` — за вредность, ненормированный | ст. 116–119 | длительность по ЛНА |
| `student` — учебный | ст. 173–176 | справка-вызов обязательна |
| `maternity` («декрет») | ст. 255 | больничный 140/156/194 дн. `[model knowledge — verify]` |
| `childcare` — по уходу до 3 лет | ст. 256 | отпуск по заявлению; мама может работать part-time без потери пособия |
| `sick` — временная нетрудоспособность | ст. 183; ФЗ-255 | справка/электронный больничный; продление — новая запись |
| `unpaid` — без сохранения | ст. 128 | обязательные категории (пенсионеры, инвалиды, смерть в семье...) |
| `special` — доноры, чернобыльцы и др. | отдельные НПА | смотреть НПА `[model knowledge — verify]` |
| `remote` — для удалёнщиков (компенсация) | ст. 312.x | если применимо |

## Обязательные действия по типам (для флагов tracker'а)

- **Ежегодный (annual):** график отпусков ст. 123 до 17 декабря; уведомление
  о начале под подпись — **не позднее чем за 2 недели** (ст. 123 ч. 3);
  нельзя не давать отпуск 2 года подряд; запрещено заменять отпуск
  компенсацией (ст. 126) — компенсируется только свыше 28 дней и при
  увольнении (ст. 127).
- **Декрет (maternity):** больничный лист → приказ в 10 дней с момента
  подачи `[model knowledge — verify]`; далее → childcare.
- **По уходу до 3 лет (childcare):** заявление + свидетельство о рождении;
  ежегодный отпуск — полный (ст. 260); **увольнение в этот период — 🔴
  только по ликвидации** (ст. 261).
- **Больничный (sick):** оплата — первые 3 дня за работодателя, дальше
  СФР
  `[model knowledge — verify]`; **нельзя увольнять на больничном по
  инициативе работодателя** (ч. 6 ст. 81) — это главный флаг tracker'а.
- **Учебный (student):** справка-вызов; сессия — сохранение среднего.
- **Без содержания (unpaid):** лимит для «обязательных» категорий; для
  остальных — по соглашению сторон; в стаж для отпуска входит только 14
  дней/год (ст. 121 `[verify]`).

## Структура записи

```yaml
- id: leave-2026-041            # последовательный
  worker_id: w-0142             # псевдоним, НЕ ФИО
  role: Ведущий аналитик
  type: annual                  # из таксономии
  start_date: 2026-07-01
  planned_end: 2026-07-28
  status: scheduled             # scheduled / active / extended / interrupted / completed / cancelled
  days: 28
  basis: "График отпусков, приказ №112-о от 2026-06-20"
  notice_given: 2026-06-14      # когда уведомили под подпись (ст. 123)
  linked_leave_id:              # при продлении/переходе (maternity→childcare)
  created: 2026-06-20
  updated: 2026-06-20
  notes: ""
```

## Guardrails

- **Только псевдонимы/ID** в YAML — реестр не личное дело.
- Не оценивать спорные ситуации в момент записи — только зафиксировать и
  связать с нормой: «если отпуск по уходу, а планируют уволить —
  termination-review, ст. 261».
- Если дата действия (уведомление, приказ) нарушена — не «постфактум
  оформить», а пометить `⚠️ нарушение уже состоялось` (для termination
  рисков это аргумент работника в суде).

## What this skill does not do

- Не заменяет кадровый учёт (табель, приказы — HRIS/HR).
- Не считает отпускные (средний заработок — wage-hour-qa + бухгалтерия).
