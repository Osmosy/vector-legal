# /leave-tracker — дедлайны по отпускам и больничным

Показывает **только записи с требующимися действиями** и объясняет, почему.
Не статус-борда.

## Инструкции

1. **Прочитать реестр:**
   `~/.hermes/legal/employment-legal/leave-register.yaml` (создаётся
   log-leave). Если реестра нет — «Реестр пуст. Зарегистрируйте первый
   отпуск через log-leave».

2. **Проверять каждую запись с `status` ≠ `completed/cancelled` по
   дедлайн-таблице ниже.**

3. **Выход:** только действия + ближайший дедлайн. Не перечислять всё

## Дедлайн-таблица (RF-специфика)

| Запись | Когда действие | Что делать |
|---|---|---|
| `annual` на подходе | `start_date - 14 дней` | Подпись работника на уведомлении о начале отпуск (ст. 123 ч. 3) получена? Нет → 🔴 |
| `annual` в течение года | ежегодный чек | График отпусков на **новый год** утверждён до **17 декабря** и с работниками ознакомлен? (ст. 123) |
| `annual` — накопление | `start_date` в текущем году не запланирован, прошло > полугода | Отпуск за 2 года подряд — запрещён (ст. 124); часть > 28 дней допустимо компенсировать только письмом-заявлением |
| `maternity` конец близко | `planned_end - 30` | Переход в childcare: заявление до окончания больничного; непрерывность права — 🔴 контроль |
| `childcare` активен | любой запрос на увольнение | **⛔ Увольнение по инициативе работодателя запрещено (ст. 261)**, кроме ликвидации. Любой termination-review по этому работнику → сразу флаг |
| `sick` активен | каждый запрос на увольнение/сокращение | **⛔ Увольнение по инициативе работодателя запрещено (ч. 6 ст. 81)**. Дата увольнения смещается до закрытия больничного |
| `sick` > 4 мес. непрерывно | длительный больничный | Сам по себе не основание для увольнения (кроме отдельных норм об инвалидности и п. 5 ст. 83 — утрата трудоспособности `[model knowledge — verify]`) — флаг на консультацию |
| `student` | `start_date - 5 дней` | Справка-вызов приложена? Приказ готов? |
| `unpaid` — «обязательные» категории | при превышении лимита | Лимиты ст. 128 (пенсионеры по возрасту — до 14 дней, инвалиды — до 60 `[model knowledge — verify]`) |
| Любая leave-запись | termination-review упомянул работника | Cross-check: работник в активном отпуске? → 🔴 флаг в termination |

## Дополнительно

- **Беременность в штате → childcare/maternity:** увольнение беременной —
  только ликвидация + справки о переводе (ст. 261). Все действия по
  termination при беременности — через termination-review с флагом.
- **График отпусков (annual planning):** если ноябрь-декабрь — напомнить:
  график на следующий год должен быть утверждён **не позднее чем за 2
  недели до 1 января** (ст. 123), с учётом мнения профсоюза (если есть).
- **Категории, имеющие право выбирать время отпуска** (вне графика): мужья в
  период отпуска по беременности жены; совместители по своему желанию...
  `[model knowledge — verify]` — при запросе такого работника отказать по
  «не по графику» нельзя.

## Выход

```markdown
# Leave-tracker — [дата]

**Требуют действия: [N]**

| ID | Работник | Тип | Дедлайн | Действие | Срочно |
|---|---|---|---|---|---|
| leave-2026-007 | w-0092 | annual | 2026-06-14 (−2 дня) | Подпись на уведомлении | 🔴 |

**Записи в норме: [N] (не перечислены)**

**Новые 🔴 с последнего прогона:** [описание или «нет»]
**Заклонированные ранее срабатывания:** [ID]
```

Если `🔴` — предлагать действие сразу: «Подготовить уведомление/приказ?».

## Guardrails

- Реестр — только псевдонимы (см. log-leave).
- Не делать выводов по одной строке реестра: перед флагом ⛔ проверить
  status и linked_leave_id (может, уже childcare, а не maternity).
- Даты дедлайнов — рабочие дни по производственному календарю РФ;
  holiday-фоллбэк: попадание на праздник — не переносит срок
  автоматически, проверить норму `[verify]`.

## What this skill does not do

- Не меняет реестр (это log-leave).
- Не утверждает график отпусков — только напоминает о сроках (ст. 123).
