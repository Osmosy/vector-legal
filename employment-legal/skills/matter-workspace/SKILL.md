# /matter-workspace

Управление рабочими пространствами дел. Файлы дел:
`~/.hermes/legal/employment-legal/matters/<slug>/`.

## Когда это нужно

- **Firm/мультиклиент** (юридическая фирма или клиника, ведущая несколько
  работодателей): обязательная изоляция между клиентами.
- **In-house**: обычно **не нужен** — отдельные кейсы сотрудников
  (расследование, увольнение, leave) ведутся practice-level файлами плагина
  (`investigation-*`, `leave-tracker`). Если in-house всё же хочет изолировать
  деликатный кейс (например, расследование в отношении руководителя) —
  допустимо завести matter, но помнить, что `Cross-matter context: off`
  скрывает его файлы от других скиллов.

Проверить `## Matter workspaces` в practice-level CLAUDE.md. Если
`Enabled: ✗` (дефолт in-house) — сообщить: «Matter workspaces выключены
(in-house). Навыки работают на practice-level. Включить? Меняю флаг в
профиле по подтверждению» — и, если пользователь настаивает, включить.

## Storage layout

```
~/.hermes/legal/employment-legal/matters/<slug>/
├── matter.md         # стороны, тип, ключевые факты, overrides
└── history.md        # аппенд-лог действий по делу
```

Слаг: короткий, без ПДн (не «ivanov-sud», а «ispitanie-2026-07» или
«klient-a-rassledovanie»).

## Активное дело — в practice CLAUDE.md

Активное дело фиксируется в `~/.hermes/legal/employment-legal/CLAUDE.md` →
`## Matter workspaces` → `**Active matter:**`. Все навыки читают его оттуда.

## Subcommand logic

### `new <slug>`

1. Проверить, что slug уникален: `list`. Если существует — спросить про
   `switch`.
2. Создать папку, `matter.md` (шаблон ниже), `history.md` (seed).
3. Спросить стороны/тип/факты; заполнить matter.md от ответов.
4. Спросить: переключиться на новое дело сейчас?
5. Дописать строку в `history.md`: `[дата] дело создано [кто]`.

### `list`

Таблица: slug | тип | создано | Active? | Открыт/закрыт.

### `switch <slug>`

1. Прочитать matter.md дела (если существует).
2. Обновить `**Active matter:**` в practice CLAUDE.md.
3. Подтвердить: «Активное дело: [slug]. Context: [кратко из matter.md]».

### `close <slug>`

1. Подтвердить: «Закрыть [slug]? Архивирую (файлы остаются, активным
   становится none).»
2. Пометить в matter.md: `Status: closed [дата]`.
3. Если это активное дело — `Active matter: none`.

### `none`

Отвязать активное дело: навыки работают на practice-level.

## `matter.md` template

```markdown
# Дело: [Клиент/работодатель] — [короткое описание]
## Стороны
## Тип дела
(найм / увольнение / расследование / leave / классификация / проверка ГИТ)
## Key facts
## Matter-specific overrides
(что в этом деле отличается от practice profile; только то, что уже
подтверждено клиентом и записано юристом)
## Related matters
## Confidentiality note
(что здесь особого по ПДн; ст. 86, 88 ТК — не раскрывать третьим лицам)
```

## Guardrails

- **Чужие дела не читать без `Cross-matter context: on`.** При попытке —
  отказ и предложение переключиться. Критично для ПДн работников.
- Слаг без ПДн: ФИО работника — в matter.md как «работник», не в имени
  папки.
- Проверить practice CLAUDE.md перед любым subcommand, кроме `new`.

## What this skill does not do

- Не переписывает practice profile — только флаг активного дела.
- Не удаляет файлы закрытых дел (архив, не удаление).
