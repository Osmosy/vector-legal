# /investigation-open — открыть служебное расследование

Загружает фреймворк `internal-investigation` (Mode 1) и создаёт постоянную
структуру расследования.

## Инструкции

1. **Загрузить профиль** `~/.hermes/legal/employment-legal/CLAUDE.md`
   (эскалации, категории защиты, PДн-правила).
2. **Follow the framework — Mode 1 Open** (см. `internal-investigation`):
   intake-таблица, конфликт интересов, быстрые срочные меры.
3. **Создать структуру**
   `~/.hermes/legal/employment-legal/matters/investigations/<slug>/`
   (log.md, sources.md, interviews/, evidence/, memo.md — пустые скелеты).
4. **Сгенерировать чеклист источников** (sources.md) под конкретную
   ситуацию: какие документы/логи/опросы нужны.
5. **Зафиксировать intake в log.md** первой записью.
6. **Эскалация по intake:** если subject — руководитель/член профсоюза/
   категория ст. 261/связь с проверкой госоргана — сразу эскалировать по
   матрице.
7. **Вывод:** slug, что создано, ближайшие 3 действия с дедлайнами
   (особенно: сроки ст. 193 — 1 мес. на взыскание со дня обнаружения —
   уже идут!).

## Shared guardrails (канон — practice profile)

**Reviewer note / decision tree / Destination check / Provenance /
No-silent-supplement / Currency trigger / Large input** — см.
practice profile (`~/.hermes/legal/<domain>/CLAUDE.md` → `## Shared
guardrails`, `## Outputs`). Блоки канонизируются там; если текст навыка
расходится с профилем — профиль контролирует.


## Слаг

`inv-YYYYMM-<тема>` например `inv-202608-kassa недостача`. Без ФИО.

## Примеры

- «Коллега пишет, что руководитель давит на смену графика после
  беременности» → intake + флаг реталиации + категории ст. 261.
- «Недостача в кассе» → чеклист: инвентаризация, договор о
  матответственности, акты, объяснения ст. 193.

## What this skill does not do

- Не проводит опросы сам — только готовит структуру и вопросы.
- Не квалифицирует вину в intake — это работа memo после сбора данных.
