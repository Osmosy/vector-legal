# /legal-research-ru — правовое исследование по российскому праву

## Matter context

Только для firm-практик; in-house — practice-level.

## Purpose

Собирает правовую базу для ответа: как суды применили норму (Постановления
Пленума ВС, обзоры практики, определения СК), что говорит закон (текущая
редакция нормы), где практика расходится. Выход — исследовательский отчёт с
provenance-тегами у каждой цитаты, а не ответ по интуиции.

## Что уместно

- Как суды решали вопрос X (для этого — kad.arbitr.ru, sudrf.ru, ПП ВС)
- Элементы состава или защиты требования, governing standard в РФ
- Как толкуется статья/норма, есть ли конфликт практики
- Аргументы обеих сторон по неустоявшемуся вопросу
- Что изменилось с даты [X] в редакции нормы/приказа/НПА
- Сравнение практики разных округов (АС МО, АС СПб, АС МО…)

## Что НЕ уместно (redirect)

- **Полный текст конкретного документа** → найти черезКонсультантПлюс или
  официальные источники; навык не выкачивает полные тексты
- **Summary отдельной статьи закона** → прочитать текст напрямую
  (pravo.gov.ru)
- **Аналитика-запросы** («как часто судья X решал в пользу…») → не в scope
- **Расчёт последнего срока подачи** → для этого есть отдельные навыки
  (deadlines в litigation-legal)
- **Прогноз исхода дела** → не в scope; см. Risk-калибровку в practice profile
- **Drafting** (исковое, отзыв) → litigation-legal/brief-section-drafter

## Источники (по приоритету provenance)

| Тег | Источник | Что брать | Надёжность |
|---|---|---|---|
| `[pravo.gov.ru]` | Официальный интернет-портал правовой информации | действующая редакция НПА, даты вступления | первоисточник |
| `[kad.arbitr.ru]` | Картотека арбитражных дел | арбитражная практика по ИНН/судье/делу | первоисточник |
| `[sudrf.ru]` | ГАС «Правосудие» | СОЮ (гражданские, уголовные) | первоисточник |
| `[КонсультантПлюс]` | КонсультантПлюс (free через web_search) | судебная практика, комментарии, обзор-статьи | secondary, проверять |
| `[vsrf.ru]` | Верховный Суд РФ | Пленумы, обзоры практики | первоисточник |
| `[user provided]` | пользователь вставил ссылку/текст | — | проверяется им |
| `[model knowledge — verify]` | всё остальное | — | проверка перед использованием |

**Нет официального API к КонсультантПлюс / Гарант / ФИПС.** Всё через
web_search — поэтому каждая цитата получает `[model knowledge — verify]` или
`[web search — verify]` и проверяется против первоисточника до опоры на вывод.

## Workflow

### Шаг 1: Сформулировать research question

Не «проверь судебную практику по неустойке», а: «Практика АС Московского
округа по снижению неустойки по ст. 333 ГК при договорах между
предпринимателями в строительных договорах за 2024–2026 гг.». Если вопрос
широкий — предложить разбиение на 2–3 под-вопроса.

### Шаг 2: Многошаговый цикл (research loop)

Для каждого под-вопроса:

1. **Пленум/обзоры ВС первыми.** Если есть ПП ВС по теме — это де-факто
   authoritative interpretation. Тег `[vsrf.ru]` / `[model knowledge —
   verify]` (пока не проверено), после web_search против vsrf.ru — тег по
   реальному источнику.
2. **Тексты норм через pravo.gov.ru.** Для каждой упомянутой статьи —
   текущая редакция. Currency trigger: если норма менялась в последние 12
   мес — проверить `[settled — подтверждено YYYY-MM-DD]` после сверки.
3. **Судебная практика через kad.arbitr.ru.** Ищи по ключевым словам +
   норме, фильтруй по округам и годам. Позиции из реальных дел процитировать
   с номером дела и судом.
4. **Вторичные источники** (КонсультантПлюс, статьи) — тег secondary и
   `[web search — verify]`, только чтобы направить к первичному (никогда
   как самостоятельное подтверждение).
5. **Не найти → не выдумать.** Три состояния (no silent supplement):
   (a) web_search + `[web search — verify]` → (b) сказать «покрытие тонкое»,
   предложить (i) углубить запрос, (ii) сменить источник, (iii) остановиться.
   Ни в каком случае не подставлять «типичную практику» из модели без флага.

### Шаг 2: Quote-to-proposition check

Перед цитированием найденного судебного акта: прочитать фрагмент и
убедиться, что это holding по нужному вопросу (не dicta, не dissent, не
цитата из другой нормы, не отвергнутый аргумент). Не подтверждается →
`[retrieved but verify support]`.

### Шаг 3: Tool-vs-model conflict

Если найденный источник расходится с модельным знанием («суд применил
норму Y, а я думаю — Z») — показать оба: «Источник [X]. Модельное знание —
[Y]. Проверяйте против первоисточника. Молча предпочесть tool ИЛИ модель
нельзя. Расхождение — сигнал.»

### Шаг 4: Собрать отчёт

```markdown
[HEADER по профилю ## Выходные документы]

**Дата:** [YYYY-MM-DD]

> - **Под-вопросы:** [N]
```

### Шаг 4: Decision tree

> **Что дальше?**
> 1. **Подготовить мемо/иск** — на основе отчёта
> 2. **Углубить исследование** — конкретный под-вопрос
> 3. **Взять внешнего юриста** — если практика противоречива
> 4. **Наблюдать** — добавить в verification-log с повторной проверкой

## Quality checks

- [ ] Question уточнён до research-able (не прогноз, не аналитика, не полный текст)
- [ ] Пленум/обзоры ВС проверены первыми
- [ ] Текущие редакции через pravo.gov.ru (или с флагом «не проверено»)
- [ ] Каждый судебный акт: суд, номер дела, дата, цитата verbatim
- [ ] Противоречия практики выделены, не замазаны
- [ ] Quote-to-proposition проверка на каждую цитату
- [ ] Каждой цитате — provenance-тег
- [ ] Отчёт в practice-profile формате (header + Reviewer note + decision tree)
