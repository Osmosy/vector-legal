# Gap Surfacer — полный трекер пробелов соответствия

## Per-send confirmation — no exceptions

Каждое письмо/сообщение/Telegram-пост, которые этот навык готовит во
внешний канал (владельцу gap'а, руководству), — показывается пользователю
ПОЛНОСТЬЮ и отправляется только после явного подтверждения. Без
исключений: автоматика не пишет руководству от имени юриста.

## Matter context

Проверить `## Matter workspaces` в practice profile; для firm — уточнить
дело. Трекеры: practice-level
`~/.hermes/legal/regulatory-legal/gap-tracker.yaml` (или
`matters/<slug>/gap-tracker.yaml` при включённых workspaces).

---

## Purpose

Diff нашёл пробелы. Пробелы без владельца и дедлайна не закрываются —
тонут. Этот навык держит очередь пробелов живой: статус, напоминания,
эскалации, честный «risk-accept» вместо вечного «в работе».

## Трекер

`gap-tracker.yaml`:

```yaml
- id: GAP-007
  requirement: "Требование #3 — реестр оборудования в ФГИС"
  regulation: "Приказ [реквизиты], [дата]"   # сверено по pravo.gov.ru [дата]
  deadline: 2026-10-01
  owner: [роль/имя]
  status: open            # open | in_progress | closed | risk_accepted | deferred
  opened: 2026-08-14
  source: "policy-diff от 2026-08-14"
  notes: ""
```

**Правила полей:**
- `deadline` — юридическая дата из акта (не «желаемая»); для
  переходных положений — конец переходного срока
- `owner` — роль или имя из матрицы эскалаций профиля; «команда» — не
  владелец
- `regulation` — реквизиты акта с датой последней сверки (`[pravo.gov.ru]`
  / `[verify]` если только из web_search)

## Режимы

### Режим 1: Ingest из policy-diff

После запуска policy-diff: «Занести пробелы в трекер?» — да:

- Для каждого 🔴/🟠 пробела — запись с дедлайном из требования
- Порядковые ID `GAP-NNN`
- Показать все записи до записи в файл, подтвердить

Не ингестить 🟢/⚪ автоматически — предложить вручную.

### Режим 2: Статус-отчёт

```markdown
[TIER HEADER]

# Открытые пробелы — [дата]

### Bottom line
[1–2 строки: N открытых, M просрочено, K критичных, самая близкая дата]

### 🔴 Просрочено
| ID | Требование | Дедлайн | Просрочено | Владелец |
|---|---|---|---|---|

### 🟠 Дедлайн < 30 дней
[Таблица]

### 🟡 Открыто
[Таблица]

### 👀 Watch items (forward-looking — pre-rule)
| ID | Проект НПА | Ожидаемое требование | Гонг | Владелец |
|---|---|---|---|---|
*Не являются действующими обязательствами — кандидаты из comment-tracker.*

### In progress
[Статус по каждому: что сделано, когда обещано]

### Recently closed
[Последние закрытия — для контекста]
```

### Consequential gate (закрыть пробел / сертифицировать соответствие)

- `close` — требует явного подтверждения пользователя и указания, чем
  закрыт (документ/процесс/изменение). Автоматически «закрыть всё
  просроченное» — никогда
- Отчёт «мы соответствуем» для внешних (руководство, аудитор, заказчик
  по 44-ФЗ) — consequential: после драфта спросить подтверждение.
  Помечать: «на основе трекера, не правовое заключение»

### Режим 3: Close gap

- Спросить: чем закрыт (документ, процесс, правка политики), дата
- `status: closed`, `closed: [дата]`, evidence-link
- Обновить verification log, если факт проверялся

### Режим 4: Risk-accept gap

- Спросить: обоснование, кто принял (имя/роль!), дату пересмотра
- `status: risk_accepted`, поля `accepted_by`, `rationale`,
  `review_date`
- В статус-отчёте risk-accepted видны отдельной секцией — не растворяются
- Review_date наступил → снова в открытые с пометкой

## Config-dependent fallbacks

- **Пользователь просит напоминания, cron не настроен** («Запланированные
  задачи ✗»): сказать, что напоминания не придут автоматически, дайджест
  — по запросу `gaps`/`gap-surfacer report`
- **Telegram настроен:** сводка 🔴 секции — одной карточкой; без
  подтверждения — не постить (per-send confirmation)

## Integration: reg-change-monitor agent

Если установлен монитор-агент (см. README плагина), он подсвечивает
изменения статуса актов по открытым gap'ам (акт отменён/перенесён — флаг
на gap). Здесь — только учёт флагов, не их генерация.

## Close

Decision tree: 1. **Напоминания владельцам** (черновики, per-send
confirmation) · 2. **Redraft** для критичного gap'а · 3. **Эскалировать**
просроченное · 4. **Обновить трекер** · 5. Другое.

## Reviewer note

Каждый статус-отчёт и каждое действие с трекером — с блоком
`⚠️ Reviewer note` по формату practice profile: источники (реквизиты
актов — `[pravo.gov.ru]` проверены/`[verify]`), покрытие, флаги,
перед опорой на вывод. Даты дедлайнов копируются из требования
шага 2 policy-diff, не «оцениваются».

## Что этот навык не делает

- Не оценивает «насколько хорошо мы соответствуем» — только
  документирует очередь
- Не закрывает gap'ы молча и не принимает риски без явного человека
- Не пишет во внешние каналы без полного показа и подтверждения
