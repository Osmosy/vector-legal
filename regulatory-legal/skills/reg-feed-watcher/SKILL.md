# /reg-feed-watcher — регуляторный мониторинг РФ

## Purpose

Периодическая проверка регуляторной среды: новые НПА по watchlist,
проекты в обсуждении (дедлайны!), правки в госзакупках, гильотина.
Выход — дайджест, который юрист читает за 3–5 минут и решает, что
эскалировать.

## Загрузить контекст

1. `~/.hermes/legal/regulatory-legal/CLAUDE.md` — watchlist, materiality,
   feed-конфигурация. Плейсхолдеры → `[PROVISIONAL]` на generic watchlist
   (пустой) и честная пометка, что профилирования не было
2. Дату последней проверки — из verification log / последнего дайджеста
   (путь в профиле). Нет — спросить окно («проверить за последние N дней?»)

## Workflow

### Шаг 0: Coverage check

Сверить watchlist с запрошенным фокусом: отрасли из профиля (напр.
«сельхоз/производство» — Минсельхоз, Россельхознадзор, Долгосрочно.рф,
Минпромторг) покрыты источниками? Явный пробел (смотрим «закупки», но нет
ФАС/44-ФЗ источника) — заметить один раз сверху дайджеста:

> **Coverage gap:** watchlist включает [категорию], но фидов этой
> категории нет. Добавить через `cold-start-interview --redo`?

Не нудить повторно: «skip X» записывается в профиль.

### Шаг 1: Pull

**Tier 1 — всегда (бесплатно):**

- **pravo.gov.ru** — официальный портал НПА: web_search (или прямой
  запрос к разделам официального опубликования) по ведомству, реквизитам,
  дате. Результаты — `[pravo.gov.ru]` только при реальном извлечении
  карточки НПА в этой сессии; иначе `[web search — verify]`
- **Сайты регуляторов:** страницы «новости/документы» watchlist-ведомств
  (ЦБ, Минцифры, РКН, ФСТЭК, Роспотребнадзор, ФАС, Минсельхоз,
  Россельхознадзор, Минпромторг). RSS нестабильны — web_search по
  «site:<домен> <тема>» с пометкой даты
- **Долгосрочно.рф** — госпрограммы, отборы, субсидии (если отрасль
  сельхоз/производство)
- **Регуляторная гильотина (ПП №1128):** периодическая сверка — не
  отменены ли обязательные требования, действующие для компании `[verify]`

**Tier 2 — по конфигурации:** КонсультантПлюс/Гарант (через web_search,
`[verify]`), отраслевые рассылки, которые пользователь вставляет.

**Тиры НЕ перемешивать в выводе молча:** тег источника на каждом айтеме.

**No silent supplement.** Мало результатов — доложить как есть:
«Проверка вернула N позиций по [регуляторам]. Похоже на слабое покрытие
[темы]. Варианты: (1) расширить окно, (2) другой источник, (3) web_search
с тегом `[web search — verify]`, (4) стоп. Что делаем?»

**Secondary sources:** правовые обзорщики (Jurist, Pravo.ru, отраслевые
телеграм-каналы) — `[secondary source]`; не классифицировать как
«всегда важно» по вторичке без трассировки до первоисточника.

### Шаг 2: Classify по materiality из профиля

| Тип | Сопоставить с порогом |
|---|---|
| Новый НПА (опубликован на pravo.gov.ru) | обычно «всегда важно» |
| Проект НПА (обсуждение на regulation.gov.ru) | «обзорно» + **обязательно логировать дедлайн обсуждения** |
| Приказ ведомства с требованиями к отрасли | «всегда важно» при попадании в отрасль |
| Изменения 44-ФЗ/223-ФЗ, КТРУ/ТРУ | «всегда важно» для закупщиков/поставщиков |
| Проверки, санкции ФАС | отрасль совпала → важно; смежно → обзорно |
| Гильотина: отмена требований | «всегда важно» если отменяют обязательное требование компании |
| Разъяснения, письма | обзорно |
| Новости/кадры ведомств | FYI/skip |

**Проект НПА — особо:** это не действующее право. Но дедлайн обсуждения
реален, и направление сигналят. Отдельная ветка: не «gap», а
`comment-tracker` (status: undecided), дедлайн в дайджесте, маршрут на
`policy-diff` только как pre-positioning.

### Шаг 3: Enrich

Для каждого элемента выше FYI: одной строкой что изменилось · почему
может касаться нас (relevance hook) · ссылка/реквизиты · ключевая дата
(вступление/дедлайн обсуждения).

FYI не аннотировать — только счётчик.

## Выход: Регуляторный дайджест

```markdown
[HEADER — по профилю]

# Регуляторный дайджест — [дата]
**Окно:** [с последней проверки / даты]
**Фиды:** [что проверено]

### Bottom line
[1–2 строки: сколько позиций, есть ли срочное]

### 🔴 Всегда важно
**[Название акта]** — [регулятор], [реквизиты], [дата]
- **Что:** [одна строка]
- **Почему нам:** [relevance hook]
- **Ключевая дата:** [вступление в силу]
- Источник: `[pravo.gov.ru]` / `[web search — verify]`

### 🟡 Обзорно
[Аналогично, короче]
**[Проект НПА]** — обсуждение до [дата] → маршрутизируется в `comments`
(дедлайн записан в comment-tracker)

### 📝 FYI
[N позиций: однострочный список тем]

---

**⚠️ Reviewer note**
- **Источники:** [N позиций `[pravo.gov.ru]` проверено · M позиций
  `[web search — verify]` — проверить по первоисточнику]
- **Покрытие:** [watchlist-регуляторы проверены все / пропущены …]
- **Перед опорой:** [реквизиты сверить по pravo.gov.ru перед решениями]
```

## Config-dependent fallbacks

- **Фид-конфигурация пуста:** использовать только web_search по pravo.gov.ru
  + отрасль из company-profile; добавить: «Это дайджест по дефолтным
  источникам — watchlist не настроен. Запусти `cold-start-interview`».
- **Telegram настроен:** дайджест одной телеграм-карточкой по House style;
  иначе — файлом.

## Handoff

- Новые требования к действующим политикам → `policy-diff`
- Дедлайны обсуждений → `comments`
- Пробелы соответствия → `gap-surfacer` (через `policy-diff`)

## Close

Decision tree: 1. **Разобрать [акт]** → policy-diff · 2. **Комментарий**
к проекту → comments · 3. **Обновить watchlist** → customize ·
4. **Ничего** · 5. Другое.

## Что этот навык не делает

Не даёт правовой оценки актов (только сигнал + релевантность), не строит
gap-анализ (это policy-diff), не подменяет проверку реквизитов по
pravo.gov.ru.
