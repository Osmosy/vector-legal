# Письмо клиенту: рутинная переписка

## Назначение

Клиника шлёт много рутины: «ваш приём во вторник в 14:00», «принесите, пожалуйста,
договор найма», «мы подали ваши возражения». Навык делает это из шаблонов,
чтобы студенты не набирали одно и то же письмо каждую неделю.

**Scope: только рутина.** Содержательный совет, плохие новости, стратегия —
это `status client` или разговор, а не шаблонное письмо.

## Shared guardrails (канон — practice profile)

**Reviewer note / decision tree / Destination check / Provenance /
No-silent-supplement / Currency trigger / Large input** — см.
practice profile (`~/.hermes/legal/<domain>/CLAUDE.md` → `## Shared
guardrails`, `## Outputs`). Блоки канонизируются там; если текст навыка
расходится с профилем — профиль контролирует.


## Принцип простого языка — обязательный для этого навыка

Клиенты клиники — люди **без юридического образования**. Каждое письмо
проходит проверку:

- **Уровень чтения:** по plain-language стандартам профиля (дефолт — уровень
  массовой газеты; короткие предложения)
- **Юр-термин → перевод при первом упоминании:** «Мы подали „возражения" —
  это документ, в котором мы объясняем суду вашу позицию»
- **Запрещены** (список в профиле, дефолт): «в соответствии с», «настоящим
  направляем», «проинформировать», латинизмы, непояснённые термины
- **Обязательные элементы каждого письма:** что произошло / что дальше /
  что клиент делает / как связаться с клиникой
- **Проверка:** «Понял бы это письмо человек, который никогда не был в суде?»
  Если нет — переписать до отправки на сверку.

## Загрузка контекста

`~/.hermes/legal/legal-clinic/CLAUDE.md` → plain-language стандарты,
супервизорская модель, контакты клиники.

## Педагогическая проверка

Гайд `~/.hermes/legal/legal-clinic/guides/<категория>.md` → `pedagogy_posture`:

- **`guide` (дефолт):** выдать структуру и чеклист (обязательные элементы,
  plain-language цели); студент пишет каждую секцию; обратная связь (регистр,
  уровень чтения, обязательные элементы, что упущено). Заполнить секцию —
  только после одной попытки студента.
- **`assist`:** написать письмо целиком; пометить для проверки студентом;
  студент правит и учится редактурой.
- **`teach`:** письмо не писать. Студент пишет, навык задаёт направляющие
  вопросы и даёт feedback; образец — только после двух попыток и только
  проблемной секции.

Без гайда — `guide`. Выход всегда содержит строку «**Режим педагогики:
[assist/guide/teach]** — задан гайдом супервизора. …»

## Подпись и раскрытие статуса студента

По положению клиники: в письмах, подписанных студентом, студент называется
студентом клиники («студент-юрист юр. клиники»), а рядом указан супервизор,
под контролем которого идёт работа. Шаблоны ниже используют generic-форму —
привести подпись к положению клиники до отправки. **Процессуальные документы
студент не подписывает вовсе — только супервизор (SUPERVISOR-GATE).**

## Типы писем

> **Пометка ревью — ВНЕ письма.** Тег `[ИИ-ЧЕРНОВИК — сверка studenta и
> подпись супервизора по модели супервизии из профиля]` — записка студенту,
> не часть письма. Ставится над отрендеренным шаблоном (или в шапку, которую
> студент удаляет до отправки), никогда внутри письма. Если пометка попала
> в клиентскую копию — навык не сработал.

### Приглашение на приём

*Пометка для студента (не для клиента — снять до отправки):*
`[ИИ-ЧЕРНОВИК — сверка студента и подпись супервизора по модели супервизии из профиля]`

```markdown
Уважаемый(ая) [Имя Отчество],

Подтверждаем ваш приём в юридическую клинику [название]:

**Дата:** [дата]
**Время:** [время]
**Где:** [адрес / кабинет / или «по телефону [номер]»]
**С вами будет:** [имя студента]

**Пожалуйста, возьмите с собой:** [документы — из материалов дела; если
неизвестно, оставить студенту заполнить]

Если нужно перенести, позвоните нам по телефону [телефон клиники]
минимум за 24 часа.

[Имя студента]
студент-юрист, юридическая клиника [название]
под контролем супервизора [ФИО]
[Клиника] | [телефон] | [часы работы]
```

*Пометка для студента (не для клиента — снять до отправки):*
`[ИИ-ЧЕРНОВИК — сверка студента и подпись супервизора по модели супервизии из профиля]`

Если каких-то документов нет или непонятно, что имеется в виду, — позвоните
по телефону [телефон клиники], поможем.

[Имя студента]
студент-юрист, юридическая клиника [название]
под контролем супервизора [ФИО]
[Клиника] | [телефон] | [часы работы]

### Короткий апдейт

Для рутины «подали» / «ждём». (Развёрнутые апдейты → `status client`.)

*Пометка для студента (не для клиента — снять до отправки):*
`[ИИ-ЧЕРНОВИК — сверка студента и подпись супервизора по модели супервизии из профиля]`

```markdown
Уважаемый(ая) [Имя Отчество],

Коротко: [одна строка, что произошло — «Мы подали ваши возражения в суд
[дата]» / «Мы направили претензию управляющей компании [дата]»].

**Что дальше:** [одна строка — «Ждём их ответ» / «Суд назначит заседание
и сообщит нам дату»].

Вам ничего делать не нужно. Мы напишем, когда что-то изменится.

[Имя студента]
студент-юрист, юридическая клиника [название]
под контролем супервизора [ФИО]
[Клиника] | [телефон] | [часы работы]
```

## До отправки

Отправка письма клиенту — consequential action. Ворота — **SUPERVISOR-GATE**:
письмо уходит только после проверки и подписи супервизора, при любой модели
супервизии (очередь / флаги / лёгкий режим). Дополнительно:

1. Черновик прошёл супервизию по протоколу профиля (очередь / флаг /
   лёгкий режим).
2. Внутренние пометки (`[ИИ-ЧЕРНОВИК]`, любые `[VERIFY]`, `[FACT NEEDED]`)
   удалены из клиентской копии.
3. Подпись соответствует положению клиники (студент + супервизор).
4. Plain-language проверка пройдена: термины пояснены, канцеляризмы убраны,
   обязательные элементы на месте.

**Это студенческий черновик для проверки супервизором, а не финальное
письмо.** Его отправка имеет правовые последствия для клиента. Супервизор
проверяет, правит и подписывает до того, как письмо покинет клинику. Без
одобрения супервизора не отправлять.

## Проверка простого языка

По профилю клиники. Короткие предложения, без канцеляризмов, уровень чтения
выдержан. Если в шаблоне встретился термин, которого клиент может не знать, —
пояснить при первом упоминании: «Мы подали ваши „возражения" — это документ,
в котором суду объясняется ваша позиция».

## Маршрутизация супервизии

По профилю. Рутина может флагаться или нет в зависимости от модели; при
лёгком режиме письма уходят после проверки студента (но после подписи
супервизора — SUPERVISOR-GATE); при формальной очереди — даже рутина в
очередь.

## Что этот навык НЕ делает

- **Содержательный совет.** Если в письме просится «вот что я думаю о вашем
  деле» или «вам следует…» — это не рутина; сначала `status client` или
  разговор с супервизором.
- **Плохие новости.** Закрытие дела, отказ в иске, «мы не сможем помочь» —
  это требует мысли, не шаблона. Флагать супервизору.
- **Адресат — не клиент.** Суды, оппоненты, ведомства — другие навыки (`draft`
  или `status court`).
