# /build-guide — категорийный гайд супервизора

1. Загрузить `~/.hermes/legal/legal-clinic/CLAUDE.md` → роль (должен быть
   супервизор), категории, юрисдикция.
2. Использовать workflow ниже.
3. Не супервизор → остановиться и перенаправить (студенты идут в `ramp`).
4. Пройти: категория → intake-вопросы → педагогика → гейты проверки →
   межплагинные проверки → локальные регламенты.
5. Записать `~/.hermes/legal/legal-clinic/guides/<категория>.md`. Создать
   `guides/`, если нет.
6. Предложить тест-прогон: запустить `draft` в сконфигурированной позе, чтобы
   супервизор увидел, что увидит студент.

```
build-guide
```

Гайдов может быть несколько — по одному на категорию. Перезапуск — правка;
мелкие правки — прямо в файле.

# Build Guide: категорийный гайд супервизора

## Назначение

Гайд — регулятор, который превращает студенческие навыки из «сделай работу»
в «научи студента делать работу». Каждый студенческий навык читает гайд до
выхода: intake задаёт вопросы супервизора, черновики выбирают педагогическую
позу, гейты направляют к супервизору именно то, что ему важно, межплагинные
проверки оборачивают чужие навыки в супервизорскую обёртку.

Навык помогает написать гайд за 5–10 минут на категорию. Гайд — plain markdown
по известному пути; правится руками в любой момент.

**Аудитория: супервизор.** Не студенты: они идут в `ramp`, гайды не пишут.

## Work-product header

Каждый выход этого навыка — конфигурационный артефакт супервизора, не
студенческий work product. Этикетка `[ИИ-ЧЕРНОВИК — …]` на выход этого навыка
НЕ ставится — она для студенческих выходов. Файл гайда лежит рядом с
CLAUDE.md в каталоге конфигурации, не в папке дела.

## Что должен закрывать гайд

Дать как чеклист — супервизор может пройтись или взять как оглавление:

- Что студент обязан знать до касания дела? (этика, конфиденциальность,
  границы полномочий — с обязательным SUPERVISOR-GATE: ничего не уходит
  клиенту/в суд/ведомство без подписи супервизора)
- Топ-3–5 типовых ошибок студентов в этой категории, и как навык их ловит?
  (для РФ-категорий: пропуск сроков — ст. 392 ТК для трудовых, 10 суток по
  КоАП; несоблюдение досудебного порядка в потребительских; подписание
  процессуальных документов студентом)
- Когда студент обязан остановиться и взять вашу подпись? (подача,
  отправка клиенту, утверждение, стратегическая рекомендация)
- Уровень чтения клиентских писем? (plain-language стандарты по профилю)
- Какие локальные регламенты, формы и сроки обязан знать каждый студент?
- Когда навык учит, а когда делает? (по типам документов — дефолт и оверрайды)

Пройти чеклист в начале интервью, чтобы супервизор пометил, где у него твёрдая
позиция, а о чём он хочет подумать. Пропущенное — в гайде строкой «не
специфицировано — навык использует дефолты».

## Workflow

### Шаг 1: Проверка роли

Это навык супервизора. Прочитать `CLAUDE.md` → `## Кто использует` → Роль.
Не супервизор →

> Этот навык для супервизоров — он настраивает поведение студенческих
> навыков. Если ты супервизор, поставь роль «Супервизор» в
> `cold-start-interview`. Если студент — тебе нужен `ramp`, а гайд для твоей
> клиники пишет супервизор.

Остановить, если роль не супервизор.

### Шаг 2: Какая категория?

> Для какой категории дел этот гайд? (жилищные / семейные / потребительские /
> миграционные / трудовые / соцобеспечение / иное)

Ответ «иное» → короткое имя; оно станет именем файла (lowercase через дефис:
`zhilishchnye-spory.md`, `migratsionnye.md`).

Сверить с перечнем категорий клиники в `CLAUDE.md` → Профиль клиники. Если
категории там нет, отметить: «Гайд запишу, но в профиле клиники [категория]
не значится. ОК — впишешь позже через `cold-start-interview --redo`, но
client-intake не будет маршрутизировать сюда, пока категория не внесена.»

Если гайд уже существует — предложить: (a) править по секциям, (b) начать
с нуля с перезаписью, (c) сперва посмотреть, что там.

### Шаг 3: Intake-вопросы

> Что студенты спрашивают нового клиента по этой категории? Я начну с generic
> intake — говори, что добавить, убрать, переформулировать. Какие красные
> флаги? Что делает дело «хорошим попаданием» для вашей клиники, а что —
> кандидатом на направление?

Показать generic-дефолты категории — те же, что у `client-intake`. Для
категорий вне четырёх базовых попросить описать intake с нуля.

Захватить: добавить / убрать / переформулировать, красные флаги (список),
критерии попадания (что берём), критерии направления (что не берём).

### Шаг 4: Педагогическая поза

> Сколько делают навыки и сколько — студент?
>
> - **Guide (дефолт):** навык даёт структуру; студент заполняет содержание;
>   навык даёт feedback. Сбалансировано — большинство клиник стартуют здесь.
> - **Assist:** навык производит work product; студент правит и учится
>   редактурой. Быстрее всего — для высоконагруженных клиник и горящих
>   сроков.
> - **Teach:** навык не производит work product — студент пишет, навык даёт
>   сократовский feedback и только после двух попыток показывает образец.
>   Медленнее, максимально педагогика. Для семинарских форматов.
>
> Можно по типам документов (напр., teach для писем клиенту, assist для
> черновиков процессуальных документов).

Захватить позу по умолчанию и оверрайды по документам:

- `pedagogy_posture_default: assist | guide | teach`
- `pedagogy_posture_client_letter: [оверрайд]`
- `pedagogy_posture_memo: [оверрайд]`
- `pedagogy_posture_draft: [оверрайд]`

Тип документа, которого нет у навыков, — записать в блок
`pedagogy_posture_other:` с примечанием; будущие навыки прочитают.

### Шаг 5: Гейты проверки

> Какой work product требует вашей проверки до отправки? Что студент может
> отправить сам? Дефолт: всё клиенто-направленное — через проверку.

Таблица для заполнения супервизором:

| Work product | Гейт |
|---|---|
| Intake-резюме | [пишет студент; проверка на кейс-раунде / до показа клиенту / остаётся у студента] |
| Заключение (memo) | [проверяет супервизор / остаётся у студента] |
| Письмо клиенту (приглашение / запрос документов / апдейт) | [проверяет супервизор / студент отправляет сам] |
| Письмо клиенту (содержательное / плохие новости) | **всегда супервизор — нельзя переконфигурировать** |
| Черновик процессуального документа (суд / ведомство) | **всегда супервизор — подписывает супервизор — нельзя переконфигурировать** |
| Статус для суда | **всегда супервизор — нельзя переконфигурировать** |
| Research-карта | [студент работает по ней самостоятельно] |

Гейты, отмеченные «нельзя переконфигурировать», фиксированы SUPERVISOR-GATE'ом:
содержательные письма клиенту, процессуальные документы и статусы для суда
всегда идут через супервизора и подписываются им. Настраиваются только
рутинные гейты.

### Шаг 6: Межплагинные проверки

> Хотите, чтобы студенты использовали навыки других плагинов Vector Legal
> (проверки по договорам, хронологии, реестрам)? Я оберну их в супервизию:
> студент запускает проверку, вывод флагается для вашего ревью, наружу ничего
> не идёт без подписи.

Конкретные примеры по категориям:

- **Потребительские:** `product-legal` проверки типовых договоров (кредит,
  услуги), обёрнутые в супервизию
- **Трудовые:** `employment-legal` навыки разбора трудовых договоров — вывод
  флагается для супервизора до подачи
- **Миграционные:** `litigation-legal:chronology` для хронологии по
  документам клиента — флаг супервизору до подачи
- **Любая категория:** `privacy-legal:triage`, если материалы дела выходят
  за пределы клиники

Названный супервизором навык фиксируется: имя, когда используют, какой
супервизорский wrapper (всегда ревьюер / только по флагу / никогда без
супервизора).

### Шаг 7: Локальные регламенты и юрисдикция

> В каких судах/ведомствах работает клиника по этой категории? Какие
> регламенты, бланки и памятки нужны студентам?

Сверить с `CLAUDE.md` → Юрисдикция — регион и основные суды уже заданы на
cold-start. Этот шаг — для категорийных памяток (образец шапки конкретного
суда, порядок записи к мировому судье, бланки ГИТ, регламент приёма
Роспотребнадзора). Захватить короткий список указателей для студенческих
навыков.

### Шаг 8: Записать гайд

`guides/`, если нет. Структура:

**Автор:** [ФИО супервизора из CLAUDE.md]

- [критерий 1]

- `pedagogy_posture_memo: [assist | guide | teach]`

> может быть несколько — по одному на категорию.

### Шаг 9: Тест-прогон

> Хочешь посмотреть, как поза меняет опыт? Прогоню `draft` с учебным письмом
> под [поза] — увидишь ровно то, что увидит студент.

Если да — сымитировать reading гайда и выдачу в сконфигурированной позе.
Один полный прогон.

## Выход

Выход навыка — файл `~/.hermes/legal/legal-clinic/guides/<категория>.md`.
Разговор с супервизором — интервью; гайд — артефакт.

После записи — короткое подтверждение:

> **Гайд записан.** `[категория]` сконфигурирована:
>
> - Intake: [N] кастомных вопросов, [N] красных флагов, [N] критериев направления
> - Педагогика: [поза-дефолт], оверрайды: [список, если есть]
> - Гейты: [сводка — что к супервизору, что к студенту]
> - Межплагинные: [N] навыков подключено
>
> Студенты увидят эти настройки при следующем прогоне навыков по этой
> категории. Правь [путь] в любой момент.

## Что этот навык НЕ делает

- **Не конфигурирует плагин целиком.** Гайд — по категории. Общий конфиг
  (модель супервизии, юрисдикция, категории) — `cold-start-interview`.
- **Не пишет студенческий work product.** Это супервизорская конфигурация,
  не черновик для клиента.
- **Не перекрывает SUPERVISOR-GATE.** Модель супервизии задана на cold-start;
  гейты гайда уточняют её для категории, не заменяют. Содержательные письма
  клиенту, процессуальные документы и статусы для суда — всегда через
  супервизора.
- **Не даёт студенческим навыкам снять этикетку ИИ-черновика, флаги
  уверенности и приглашения к проверке.** Это общий guardrail-базис. Гайд
  меняет позу, не guardrails.
