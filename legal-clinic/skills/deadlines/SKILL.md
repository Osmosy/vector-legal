# /deadlines — сроки по делам

1. Загрузить `~/.hermes/legal/legal-clinic/CLAUDE.md` → юрисдикция, категории,
   warning-каденс.
2. Использовать workflow ниже.
3. Маршрутизация по флагу:
   - `--add`: дело, тип, описание, дата, источник, исполнитель. Запись в
     `~/.hermes/legal/legal-clinic/deadlines.yaml`. Сначала проверка дублей.
   - `--report` (дефолт): кросс-дела — просрочка, 3д, 7д, 14д; по исполнителям;
     по категориям; без исполнителя.
   - `--update [id]`: правка полей; датированная заметка.
   - `--complete [id]`: закрыть как выполненное; подтвердить со студентом,
     что документ реально подан/отправлен.
   - `--close [id]`: закрыть без выполнения; причина обязательна.
4. Любую запись подтверждать до фиксации.

```
/deadlines --add
```

```
/deadlines --report
```

# Процессуальные сроки

## Назначение

Самый большой операционный риск клиники — пропущенный срок. Студенты ведут
несколько дел, частично заняты, меняются каждый семестр. Сроки, живущие только
в голове студента, теряются на хэндов-фере, забываются в сессию, пропадают при
внезапном уходе студента из клиники. Этот навык — центральный операционный
реестр.

За пропущенный срок отвечает супервизор. Навык калиброван под эти ставки:
предупреждения срабатывают заранее, просрочка остаётся видимой, пока её явно
не закроют, хэндоверы (`/semester-handoff`) тянут список сроков дальше.

## Load context

- `~/.hermes/legal/legal-clinic/CLAUDE.md` → юрисдикция/суды, категории,
  warning-каденс (14/7/3/1), супервизоры
- `~/.hermes/legal/legal-clinic/deadlines.yaml` — реестр

**Дефолтные кадры сроков по отраслям** — для sanity-проверки расчёта
студента (не для автоматического подсчёта за него). Все значения —
`[model knowledge — verify]` до записи в отчёт:

| Тип срока | Типичный рамка | Где подтверждать |
|---|---|---|
| **ТК: увольнение (ст. 392 ч. 1)** | **1 месяц** со дня вручения копии приказа или выдачи трудовой книжки | ст. 392 ТК РФ, действующая редакция |
| **ТК: иные трудовые споры (ст. 392 ч. 1)** | **3 месяца**, когда узнал о нарушении права | ст. 392 ТК РФ |
| **ТК: невыплата после увольнения (ст. 392 ч. 2)** | **1 год** | ст. 392 ТК РФ |
| **ГПК: апелляция** | 1 месяц со дня принятия решения в окончательной форме | ст. 321 ГПК РФ |
| **ГПК: ответ на апелляционную жалобу** | 1 месяц | ст. 325 ГПК РФ |
| **КАС: административное исковое (общий срок давности)** | 3 месяца | ст. 219 КАС РФ; по отдельным главам — иные |
| **КАС: обжалование решения** | 1 месяц | гл. 14 КАС (если иной срок не установлен) |
| **АПК: ответ на иск** | в определении суда (обычно больше 15 раб. дней) | определение суда, ст. 131 АПК |
| **АПК: апелляция** | месяц после принятия решения | ст. 259 АПК РФ |
| **КоАП: обжалование постановления** | **10 суток (в ряде составов — 10 дней) со дня вручения/получения копии** | ст. 30.3 КоАП РФ; отдельные главы — 5 суток |
| **ЗоЗПП: удовлетворение требований потребителя** | 10 дней (денежные) | ст. 22 ЗоЗПП; досудебная претензия — обязательна для неустойки |
| **Претензия в сфере связи / ЖК** | 30–60 дней по ведомственным НПА | ведомственные приказы, договор управления |

База — `references/plausibility-frames/ru-frames.md` — файл клиники, который
cold-start/supervisor может уточнять под категории, которые реально ведёт
клиника. Проверка всегда по первоисточнику (pravo.gov.ru / КонсультантПлюс).

**Предположение о юрисдикции.** Кадры сроков и threshold'ы предупреждающих
отталкиваются от региона/судов из профиля. Сроки, порядок исчисления
(ст. 100 ГПК, ст. 113 АПК/КАС), восстановление сроков (ст. 112 ГПК/АПК,
ст. 95–96 КАС) и практика судов/ведомств варьируются. Если дело в другом
регионе, в ведомстве или федеральная норма конкурирует с региональной —
сверить срок с супервизором до опоры на него.

## Режимы

Флаг: `--add | --report | --update | --complete | --close` (дефолт: report)

### `--add` — новый срок

**Входы:**
- Дело (ID + имя)
- Категория (жилищные / семейные / потребительские / миграционные / трудовые / иное)
- Тип (filing / hearing / statute-of-limitations / discovery / cure-period /
  response / notice / other)
- Описание — одна строка: что должно быть сделано
- Дата (+ время, если для заседания/подачи есть жёсткий cutoff)
- Источник — откуда срок (повестка от 2026-08-20, ст. 321 ГПК, ст. 392 ТК,
  претензионный порядок по ЗоЗПП)
- Студент-исполнитель

Навык сам генерирует `id`: `[case]-[кратко]-[YYYY-MM]`. Студент подтверждает.

**Извлечение из других навыков:** когда `client-intake`, `draft` или `status`
показывают срок, они выдают готовый `--add`-блок. Студент подтверждает и
добавляет.

**Pre-add duplicate check:** если срок с тем же case_id + type + due_date
уже есть — флаг как вероятный дубль, спросить до записи.

**Sanity-проверка правдоподобия.** После того как студент внёс дату,
**навык не считает сам** — но прогоняет грубую проверку на правдоподобие
относительно типичных рамок выше для этого типа срока и флагает, если дата
далека от рамки. Это подстраховка против грубых ошибок в подсчётах, не
замена подсчёта по норме.

**Ужесточение для РФ:** подсчёт сроков в днях — рабочий/календарный,
с какого дня считать, что делать при попадании последнего дня на выходной
(перенос на следующий рабочий) — по процессуальному кодексу соответствующей
отрасли (ГПК ст. 108, АПК ст. 113, КАС ст. 100 `[model knowledge — verify]`).
Навык не считает; студент и супервизор проверяют расчёт по норме и редакции.
Ошибки подсчёта — самая частая ошибка студентов; навык обязан спрашивать
«считал супервизор?», если срок проставлен без поля источника нормы, по
которой считали.

**Логика проверки:**

1. Загрузить фрейм для этой категории из
   `references/plausibility-frames/ru-frames.md`
2. Когда студент внёс `due:` — сравнить с событие+рамка для этого `type:`
3. В рамке — записать. Молча: фрейм существует, чтобы ловить ошибки, а не
   хвалить за верную математику.
4. Вне рамки — остановиться до записи:
   > Дата вне типичного рамка для [type] в [отрасли]. [Type] сроки
   > обычно [range] от [событие]. Твоя запись: [date] — [N] дней от
   > [событие]. Пересчитай по [норма из фрейма] и правилам исчисления
   > (ст. 107–108 ГПК / ст. 113 АПК / ст. 100 КАС — поправить под отрасль).
   > Если расчёт верен (нерабочие дни, восстановление срока, специальная
   > норма) — подтверди, и я запишу. Иначе — пересчитать и запустить
   > `/deadlines --add` заново.
5. Нет фрейма для этого типа — не проверять; записать и поставить
   `warnings: no-plausibility-frame`

**Навык не считает.** Если студент в `due:` оставил `[ПОДТВЕРДИТЬ]` — записать
как есть; sanity прогоняется только на конкретной дате. Подсчёт — у студента
и супервизора.

### `--update` — правка существующего

Типичные: дата сдвинулась (отложили заседание), исполнитель сменился,
добавились заметки. Каждая правка пишет дированную заметку inline; история
видна в записи.

### `--complete` — выполнено

- Ставит `status: completed`, `completed_date: [today]`
- Подтверждает со студентом: документ реально подан/направлен
- Исчезает из активных отчётов, остаётся в yaml

### `--close` — закрыть без выполнения

Для сроков, переставших быть актуальными: дело завершилось, заявление
отозвано, клиент перестал вести дело. Требует `notes:` с объяснением.

## Warning cadence

Из профиля клиники. Дефолт 14, 7, 3, 1.

Предупреждения не приходят сами — у плагина нет scheduled-поведения. Но любой
запуск `/deadlines` (и `/status`, маршрутизирующий к нему за сроками) поднимает
всё на warning-пороге. Пропущенный срок без отметки `complete` → `status:
overdue` и остаётся в каждом отчёте до явного разрешения. Просрочка не
авто-закрывается.

## Интеграция

- **`client-intake`:** при выявлении срока — offer `/deadlines --add` с
  готовыми полями.
- **`draft`:** если черновик ссылается на срок (ответ, замечания) — offer добавить.
- **`status`:** читает `deadlines.yaml` по делу и включает будущие сроки в вывод.
- **`semester-handoff`:** читает список активных сроков уходящих дел; каждое
  хэндов-мемо тянет сроки дальше.
- **`supervisor-review-queue` (если формальная очередь):** сроки на подходе —
  приоритет в очереди ревью.

## Что этот навык не делает

- **Считает срок от события.** Если иск направлен сегодня и срок ответа —
  15 дней по ГПК, навык не делает эту математику: студент считает по норме
  и вносит дату. (Авто-подсчёт — ответственность, которую навык не берёт:
  нормы варьируются, ошибки подсчёта — самая дорогая ошибка.)
- **Подаёт или отправляет что-либо.** Только учёт дат; подача — вне плагина,
  через супервизора (SUPERVISOR-GATE).
- **Авто-уведомления.** Нет scheduled-нотификаций. Отчёт отражает warning
  при вызове, не пушит. Cron можно добавить позже — по явному opt-in клиники.
- **Переопределяет процессуальные нормы.** Если студент внёс срок,
  противоречащий норме, навык не ловит это всегда. Поэтому каждый
  нетривиальный срок — с `[ПОДТВЕРДИТЬ против нормы]` до подтверждения
  супервизором.
